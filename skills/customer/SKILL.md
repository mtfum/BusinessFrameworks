## 01. ペルソナ
**目的**: ターゲット顧客の典型像を具体的な人物として描き、チーム全体で「誰のために作っているか」を共有する

**いつ使うか**: 新規事業の企画段階、既存サービスのリニューアル時、マーケティング施策の立案時。チーム内で「顧客像」の認識がバラバラだと感じたときに特に有効。

**テンプレート**:
| 項目 | 内容 |
|------|-----|
| 名前（仮名） | |
| 年齢・性別 | |
| 職業・役職 | |
| 年収・家族構成 | |
| 居住地・ライフスタイル | |
| 価値観・信条 | |
| 課題・悩み | |
| 情報収集手段 | |
| 購買決定の基準 | |
| よく使うサービス | |
| 1日のタイムライン | |
| テクノロジーリテラシー | |

**使い方**: 実データ（インタビュー・アンケート・行動ログ等）に基づいて作成する。想像だけで作ると的外れになる。1つの事業に対してペルソナは2〜3人が適切。多すぎると焦点がぼやける。

### 記入例（B2Cサービス）
| 項目 | 内容 |
|------|-----|
| 名前（仮名） | 田中 美咲 |
| 年齢・性別 | 32歳・女性 |
| 職業・役職 | IT企業のプロジェクトマネージャー（中堅） |
| 年収・家族構成 | 年収550万円・夫（35歳SE）と2人暮らし、子なし |
| 居住地・ライフスタイル | 東京都世田谷区・平日は忙しく帰宅は21時頃。週末はカフェでリラックスしたり友人とブランチを楽しむ |
| 価値観・信条 | 「時間はお金より大切」。効率重視だがモノ選びでは品質にこだわる。サステナブルな消費に関心あり |
| 課題・悩み | 平日に買い物の時間がない。ネットで買うと失敗が多い。自分に合うものを効率よく見つけたい |
| 情報収集手段 | Instagram、友人の口コミ、Google検索、YouTube |
| 購買決定の基準 | レビュー評価、時短効果、デザインの良さ、信頼できるブランドかどうか |
| よく使うサービス | Amazon Prime、Uber Eats、Netflix、メルカリ |
| 1日のタイムライン | 7:00起床→8:30出社→12:00ランチ（デスク）→21:00帰宅→22:00〜自由時間→24:00就寝 |
| テクノロジーリテラシー | 高い。新しいアプリも抵抗なく試す |

### 記入例（B2Bサービス）
| 項目 | 内容 |
|------|-----|
| 名前（仮名） | 鈴木 健太郎 |
| 年齢・性別 | 45歳・男性 |
| 職業・役職 | 製造業（中堅メーカー）の経営企画部長 |
| 年収・家族構成 | 年収900万円・妻と高校生の子供2人 |
| 居住地・ライフスタイル | 埼玉県さいたま市・車通勤。業界団体の勉強会に月1回参加 |
| 価値観・信条 | 「データに基づく意思決定」を重視。社内のDX推進を任されているが、現場の抵抗に苦労 |
| 課題・悩み | 属人的な業務プロセスの改善、経営層への投資対効果の説明、ツール導入後の定着率の低さ |
| 情報収集手段 | 日経ビジネス、業界専門誌、展示会、LinkedInの記事、同業他社の事例 |
| 購買決定の基準 | ROIの明確さ、導入実績、サポート体制、既存システムとの連携性 |
| よく使うサービス | Salesforce、kintone、Teams、SAP |
| 1日のタイムライン | 6:30起床→8:00出社→会議3〜4件→18:30帰宅→夕食→21:00〜メール処理→23:00就寝 |
| テクノロジーリテラシー | 中程度。Excelは得意だが最新SaaSには不慣れ |

### よくある失敗
1. **妄想ペルソナ**: 実データなしに「こうであってほしい理想の顧客」を描いてしまう。結果、実際の顧客と乖離したペルソナになる
2. **ペルソナの乱立**: 「あの顧客もこの顧客も」と欲張って5人以上作ってしまい、結局どれにも焦点が合わない
3. **作って終わり**: ペルソナを作った満足感で終了し、意思決定の場で参照されない。壁に貼る、会議の冒頭で確認するなど、日常的に使う仕組みが必要

### 活用のヒント
- **インタビューは最低5人**: 定量データだけでなく、実際の顧客に「なぜそうするのか」を深掘りする定性調査が不可欠
- **定期的に更新する**: 市場や顧客は変化する。半年〜1年に1回は見直す
- **ネガティブペルソナも作る**: 「この人はターゲットではない」という像を明確にすると、施策の取捨選択がしやすくなる
- **写真やイラストを添える**: 視覚的な要素を加えることで、チーム内の共通理解が深まる

### 次のステップ
- **共感マップ**（`/customer` 02）でペルソナの内面をさらに深掘りする
- **カスタマージャーニーマップ**（`/customer` 03）でペルソナの体験を時系列で設計する
- **ジョブ理論**（`/customer` 04）でペルソナが本当に解決したいジョブを特定する
- **STP**（`/customer` 07）でターゲットセグメントの妥当性を検証する

## 02. 共感マップ
**目的**: 顧客の内面（思考・感情）と外面（行動・環境）を6つの視点で把握し、表面的なニーズの裏にある本質的な欲求を理解する

**いつ使うか**: ペルソナ作成後のさらなる深掘り、UX設計の初期段階、既存サービスの改善点を顧客視点で発見したいとき

**テンプレート**:
| 視点 | 内容 |
|------|-----|
| **Think & Feel**（考え・感じていること） | |
| **See**（見ているもの） | |
| **Hear**（聞いていること） | |
| **Say & Do**（言動） | |
| **Pain**（痛み・不満） | |
| **Gain**（得たいもの・望み） | |

**使い方**: ペルソナと組み合わせて使う。Pain→Gainの流れで自社の提供価値を検討する。チームでワークショップ形式で実施するのが効果的。付箋を使って各視点にアイデアを出し、議論する。

### 記入例（オンライン英会話サービスの30代会社員）
| 視点 | 内容 |
|------|-----|
| **Think & Feel** | 「英語ができないとキャリアが頭打ちになる」「でも忙しくてスクールに通う時間がない」「本当に上達するのか不安」「周りの同僚が海外案件を担当しているのが焦る」 |
| **See** | 同僚が英語で会議している姿、SNSで海外旅行を楽しむ友人の投稿、英語学習アプリの広告、昇進要件にTOEIC○○点と書かれた社内通知 |
| **Hear** | 上司から「次のプロジェクトは英語必須」、友人から「オンライン英会話よかったよ」、ネットで「1日15分で話せるようになる」という宣伝文句 |
| **Say & Do** | 「来月から始める」と言いつつ先延ばし。無料体験は申し込むが継続しない。通勤中にPodcastを聴くが集中できない。TOEIC参考書を買うが積読 |
| **Pain** | 継続できない自分への自己嫌悪、スケジュール調整の面倒さ、講師との相性がわからない不安、効果が見えにくいことへの焦り、費用対効果への疑問 |
| **Gain** | 海外出張で堂々と発言したい、キャリアアップにつなげたい、外国人の友人を作りたい、自分に自信を持ちたい、「英語ができる人」と認められたい |

### よくある失敗
1. **表面的な記述に留まる**: 「英語を学びたい」ではなく「なぜ学びたいか」「学べないと何が困るか」まで掘り下げないと使えない
2. **自社都合のバイアス**: 「きっとこう思っているはず」と自社に都合の良い解釈をしてしまう。実際の顧客の声に基づくことが重要
3. **PainとGainの混同**: Pain は現在の不満・苦痛、Gain は理想の状態。「もっと安くしてほしい」はPain、「コスパよく上達したい」はGain

### 活用のヒント
- **顧客インタビューの直後に作る**: 記憶が鮮明なうちに、聞いた言葉をそのまま書き出す
- **「Say & Do」と「Think & Feel」の矛盾に注目**: 言っていることとやっていることが違う箇所に、真のインサイトが隠れている
- **1つのセルに複数の項目を書く**: 箇条書きで3〜5個は出す。1つだけでは浅い
- **チーム全員で作る**: 営業・開発・CS等、顧客との接点が異なるメンバーが参加すると多角的になる

### 次のステップ
- **ジョブ理論**（`/customer` 04）でPain/Gainをジョブとして構造化する
- **カスタマージャーニーマップ**（`/customer` 03）でPainが発生するタイミングを特定する
- **バリュープロポジションキャンバス**（`/strategy`）でPain/Gainに対する提供価値を設計する

## 03. カスタマージャーニーマップ
**目的**: 顧客が商品・サービスと出会ってから購入・利用・推奨に至るまでの体験を時系列で可視化し、改善すべきタッチポイントを特定する

**いつ使うか**: サービス全体の顧客体験を俯瞰したいとき、離脱ポイントを特定したいとき、部門横断で「顧客にとっての一連の体験」を共有したいとき

**テンプレート**:
| フェーズ | 認知 | 興味・検討 | 購入・契約 | 利用 | 推奨・継続 |
|---------|-----|----------|----------|-----|----------|
| 行動 | | | | | |
| タッチポイント | | | | | |
| 思考 | | | | | |
| 感情（😊😐😟） | | | | | |
| 課題・機会 | | | | | |
| 対応部門 | | | | | |
| KPI | | | | | |

**使い方**: 感情曲線の谷（ペインポイント）が改善の最優先箇所。フェーズは事業に合わせてカスタマイズしてよい。

### 記入例（サブスクリプション型フィットネスアプリ）
| フェーズ | 認知 | 興味・検討 | 購入・契約 | 利用 | 推奨・継続 |
|---------|-----|----------|----------|-----|----------|
| 行動 | Instagram広告を見る。友人のSNS投稿で知る | アプリストアでレビューを読む。無料トライアルに登録 | 月額プランを選択。クレジットカードを登録 | 週3回ワークアウトを実施。体重を記録 | 友人に紹介。年間プランに切り替え |
| タッチポイント | SNS広告、口コミ、Google検索 | App Store、LP、比較サイト | アプリ内決済画面 | アプリのホーム画面、プッシュ通知、Apple Watch連携 | 紹介プログラム、メール、アプリ内ポップアップ |
| 思考 | 「最近運動不足だな」「このアプリ使っている人多いな」 | 「本当に続くかな」「他のアプリと何が違うの？」 | 「無料期間中に判断しよう」「月980円なら試してみるか」 | 「今日もやれた！」「メニューが単調になってきた」 | 「友達にも教えてあげよう」「年間だと2ヶ月分お得か」 |
| 感情 | 😐 やや不安 | 🤔 期待と迷い | 😊 決心 | 😊→😐 徐々にマンネリ | 😊 満足・愛着 |
| 課題・機会 | 広告の訴求が「痩せる」一辺倒で差別化できていない | 無料トライアルの導線が複雑で離脱率30% | 決済画面でのドロップ率が高い（セキュリティ不安） | 3週間目で利用頻度が低下する「壁」がある | 紹介プログラムの認知度が低い |
| 対応部門 | マーケティング | マーケティング・プロダクト | プロダクト・CS | プロダクト・コンテンツ | グロース・CS |
| KPI | 広告CTR、認知度調査 | トライアル登録率、LP CVR | 有料転換率 | WAU、継続率（Day 7/30） | NPS、紹介数、LTV |

### よくある失敗
1. **自社視点で描く**: 「我々がやっていること」のプロセス図になってしまい、顧客の実体験が抜け落ちる。あくまで顧客の行動・感情を中心に描くこと
2. **フェーズが粗すぎる**: 「購入」の一言で片付けず、「比較検討→問い合わせ→見積もり→稟議→契約」のように、実際のステップに分解する（特にB2B）
3. **理想のジャーニーだけ描く**: 現状（As-Is）を正確に描いてから理想（To-Be）を設計する。いきなり理想を描くと、現実の課題を見落とす

### 活用のヒント
- **大きな紙（模造紙）やMiroで作る**: デジタルツールを使うと共同編集しやすい
- **実データを添える**: 各フェーズの転換率、問い合わせ内容、NPSスコアなどの定量データを併記すると説得力が増す
- **感情曲線を必ず描く**: テキストだけでなく、折れ線グラフとして感情の上下を視覚化する
- **関係部門全員で作る**: マーケ・営業・CS・開発が集まると、フェーズ間の「隙間」が見つかる

### 次のステップ
- **共感マップ**（`/customer` 02）で感情の谷にいる顧客の内面を深掘りする
- **問題発見フレームワーク**（`/problem`）で特定した課題の根本原因を分析する
- **業務改善フレームワーク**（`/improvement`）でタッチポイントの改善施策を設計する
- **目標設定フレームワーク**（`/execution`）でKPIを設定し改善を実行管理する

## 04. ジョブ理論（Jobs to be Done）
**目的**: 顧客が「片付けたいジョブ（用事）」を軸に、真のニーズを発見する。競合は同業他社だけでなく「同じジョブを片付ける代替手段すべて」と捉える

**いつ使うか**: 新規プロダクト開発、既存製品が売れない原因の分析、競合との差別化ポイントが見つからないとき、イノベーションの方向性を探るとき

**テンプレート**:
| 項目 | 内容 |
|------|-----|
| **状況（When...）** | どんな状況で |
| **動機（I want to...）** | 何をしたくて |
| **期待成果（So that...）** | どうなりたいのか |

**ジョブの種類**:
- 機能的ジョブ（実用的な目的）:
- 感情的ジョブ（感じたい気持ち）:
- 社会的ジョブ（周囲からどう見られたいか）:

**ジョブの制約条件**:
- 現在の解決策（既存の代替手段）:
- 現在の解決策の不満点:
- 切り替えの障壁:

**使い方**: 「顧客はドリルが欲しいのではなく、穴が欲しい」という視点。さらに言えば「穴が欲しいのではなく、棚を壁に取り付けたい」。既存の解決策ではなくジョブに着目する。

### 記入例（ビジネスチャットツール）
| 項目 | 内容 |
|------|-----|
| **状況（When...）** | リモートワーク中にチームメンバーと業務を進めているとき |
| **動機（I want to...）** | ちょっとした確認や相談を、メールほど堅くなく素早くやり取りしたい |
| **期待成果（So that...）** | 意思決定のスピードを落とさず、チームの一体感を維持できる |

**ジョブの種類**:
- 機能的ジョブ: テキスト・ファイル・画面共有でリアルタイムにコミュニケーションする
- 感情的ジョブ: 孤独感を感じずにチームとつながっている安心感を得たい
- 社会的ジョブ: 「レスが速い＝仕事ができる人」と思われたい

**ジョブの制約条件**:
- 現在の解決策: メール、電話、対面ミーティング
- 現在の解決策の不満点: メールは返信が遅い。電話は相手の都合を考えると気が引ける。会議は設定に時間がかかる
- 切り替えの障壁: チーム全員が同じツールを使わないと意味がない。データ移行が面倒

### よくある失敗
1. **ソリューションをジョブと混同する**: 「Slackを使いたい」はジョブではない。「素早くチームと情報共有したい」がジョブ。手段ではなく目的を書く
2. **ジョブの粒度が大きすぎる**: 「仕事を効率化したい」では抽象的すぎて使えない。「外出先から見積書を即座に承認したい」くらい具体的にする
3. **感情的・社会的ジョブを無視する**: 機能的ジョブだけ分析して「スペック勝負」に陥る。実際の購買決定には感情や社会的要因が大きく影響する

### 活用のヒント
- **「なぜ切り替えたのか」を聞く**: 既存顧客に「以前は何を使っていたか、なぜ乗り換えたか」を聞くと、ジョブが浮き彫りになる
- **「不採用の理由」も宝の山**: 検討したが買わなかった人にインタビューすると、ジョブと解決策のミスマッチが見つかる
- **ジョブストーリーで書く**: 「（状況）のとき、私は（動機）したい。そうすれば（期待成果）できるから。」という一文にまとめると使いやすい
- **Forces of Progress（進歩の力学）**: 「新しい解決策への引力」「現状への不満」vs「切り替えへの不安」「現状への愛着」の4要素を分析すると、なぜ顧客が動く/動かないかがわかる

### 次のステップ
- **ペルソナ**（`/customer` 01）でジョブを持つ人物像を具体化する
- **アイデア発想フレームワーク**（`/idea`）でジョブを解決する新しいソリューションを発想する
- **戦略フレームワーク**（`/strategy`）でジョブに基づく差別化戦略を設計する
- **バリュープロポジションキャンバス**（`/strategy`）でジョブと提供価値を対応づける

## 05. パレート分析（ABC分析）
**目的**: 全体の成果の大部分を生み出す少数の要因を特定し、リソース配分の優先順位を明確にする（80:20の法則）

**いつ使うか**: 売上構成の分析、在庫管理の最適化、顧客ポートフォリオの見直し、コスト削減対象の特定、問い合わせ内容の優先度付け

**テンプレート**:
| ランク | 項目 | 数値 | 構成比 | 累積構成比 | 分類 |
|-------|------|-----|-------|----------|------|
| 1 | | | | | A |
| 2 | | | | | A |
| 3 | | | | | B |
| ... | | | | | C |

**分類基準**: A（累積〜70%）、B（〜90%）、C（〜100%）

**各ランクの対応方針**:
| 分類 | 割合目安 | 対応方針 |
|------|---------|---------|
| A | 項目の20%が全体の70%を占める | 最重要。手厚い管理・投資。個別対応 |
| B | 項目の30%が全体の20%を占める | 重要。標準的な管理。効率化の余地あり |
| C | 項目の50%が全体の10%を占める | 低優先。簡素化・自動化・場合により撤退 |

### 記入例（EC サイトの商品別売上分析）
| ランク | 商品名 | 月間売上（万円） | 構成比 | 累積構成比 | 分類 |
|-------|--------|---------------|-------|----------|------|
| 1 | プレミアム美容液 | 450 | 25.0% | 25.0% | A |
| 2 | オーガニックシャンプー | 320 | 17.8% | 42.8% | A |
| 3 | 保湿クリーム | 250 | 13.9% | 56.7% | A |
| 4 | UVカットミルク | 200 | 11.1% | 67.8% | A |
| 5 | リップバーム | 150 | 8.3% | 76.1% | B |
| 6 | ヘアオイル | 120 | 6.7% | 82.8% | B |
| 7 | ハンドクリーム | 80 | 4.4% | 87.2% | B |
| 8 | ボディソープ | 60 | 3.3% | 90.6% | C |
| 9 | 入浴剤 | 50 | 2.8% | 93.3% | C |
| 10〜 | その他12商品 | 120 | 6.7% | 100.0% | C |

**分析結果**: 上位4商品（全22商品の18%）が売上の67.8%を占めている。これらAランク商品に広告予算とLPを集中投下すべき。

### よくある失敗
1. **分析軸が1つだけ**: 売上金額だけで分析すると、利益率の高い商品や将来性のある商品を見落とす。売上・利益・成長率など複数軸で検証する
2. **Cランクを即座に切り捨てる**: Cランク商品でも、Aランク商品の購入を促す「入口商品」や、顧客満足に寄与する「品揃え商品」がある
3. **一度の分析で満足する**: 季節変動や市場変化があるため、定期的（月次/四半期）に更新する

### 活用のヒント
- **クロスABC分析**: 売上×利益率の2軸でマトリクスを作り、「売上A×利益A」「売上A×利益C」のような組み合わせで施策を変える
- **パレート図を描く**: 棒グラフ（個別値）と折れ線グラフ（累積比率）を重ねて視覚化すると、80:20の関係が一目でわかる
- **分類基準は事業に合わせて調整**: 70/90/100%は目安。取扱い品目数や事業特性に応じて60/85/100%などに変えてもよい

- **RFM分析**（`/customer` 06）でAランク顧客の行動パターンをさらに分析する
- **戦略フレームワーク**（`/strategy`）でAランク商品/顧客を中心にした戦略を立てる
- **業務改善フレームワーク**（`/improvement`）でCランクの業務効率化・自動化を検討する

## 06. RFM分析
**目的**: 顧客を購買行動の3指標（Recency・Frequency・Monetary）でセグメント化し、セグメントごとに最適なアプローチを設計する

**いつ使うか**: CRM施策の設計、メール/DM配信のセグメント分け、顧客の離反予兆の検知、ロイヤルティプログラムの対象選定

**テンプレート**:
| 顧客 | Recency（最終購買日） | Frequency（購買頻度） | Monetary（購買金額） | スコア | セグメント |
|------|-------------------|-------------------|-------------------|-------|----------|
| | 高/中/低 | 高/中/低 | 高/中/低 | | |

**スコアリング例**（各指標を5段階で評価）:
| スコア | Recency | Frequency | Monetary |
|-------|---------|-----------|----------|
| 5 | 7日以内 | 月2回以上 | 10万円以上/年 |
| 4 | 30日以内 | 月1回 | 5〜10万円/年 |
| 3 | 90日以内 | 3ヶ月に1回 | 3〜5万円/年 |
| 2 | 180日以内 | 半年に1回 | 1〜3万円/年 |
| 1 | 180日超 | 年1回未満 | 1万円未満/年 |

**代表セグメントと施策**:
| セグメント | R | F | M | 特徴 | 推奨施策 |
|-----------|---|---|---|------|---------|
| 最優良顧客 | 高 | 高 | 高 | ロイヤル顧客 | VIP特典、限定オファー、共創プログラム |
| 優良顧客 | 高 | 高 | 中 | 常連だが単価低め | アップセル、セット販売 |
| 離反リスク | 低 | 高 | 高 | かつての上客が離脱傾向 | 即座にリカバリー施策（特別クーポン、直接連絡） |
| 新規有望 | 高 | 低 | 低 | 最近初めて購入 | オンボーディング、2回目購入促進 |
| 休眠顧客 | 低 | 低 | 低 | 長期間活動なし | 再活性化キャンペーン or リスト除外 |

### 記入例（アパレルECの顧客セグメント分析）
| 顧客ID | R（最終購買） | F（年間回数） | M（年間金額） | Rスコア | Fスコア | Mスコア | セグメント |
|--------|------------|------------|------------|--------|--------|--------|----------|
| C001 | 3日前 | 月2回 | 18万円 | 5 | 5 | 5 | 最優良顧客 |
| C002 | 15日前 | 月1回 | 6万円 | 4 | 4 | 4 | 優良顧客 |
| C003 | 200日前 | かつて月1回 | 12万円 | 1 | 4 | 5 | 離反リスク |
| C004 | 5日前 | 初回 | 8,000円 | 5 | 1 | 1 | 新規有望 |
| C005 | 300日前 | 年1回 | 5,000円 | 1 | 1 | 1 | 休眠顧客 |

### よくある失敗
1. **スコア基準を業界に合わせない**: 不動産（年に何度も買わない）と日用品ECでは、FrequencyやRecencyの基準が全く異なる。自社の購買サイクルに合わせて設定する
2. **全セグメントに同じ施策**: 「全員に10%OFFクーポン」では最優良顧客の利益率を下げ、休眠顧客には効果がない。セグメント別の施策が必須
3. **Monetary偏重**: 金額だけを見ると「たまに高額購入する人」が上位に来るが、Frequencyの高い顧客のほうがLTVが高い場合も多い

### 活用のヒント
- **まずはR（Recency）を最重視**: 最終購買が近い顧客ほど次の購買確率が高い。施策の即効性を求めるならRでまず絞る
- **離反リスク顧客への対応を最優先**: RFMが「低・高・高」の顧客は、かつてのVIPが離れつつあるサイン。理由を調べ、パーソナルな対応を行う
- **セグメント間の移動を追跡する**: 月次でRFMを更新し、「新規有望→優良」への移行率や「優良→離反リスク」への移行率をKPIにする
- **LTV（顧客生涯価値）と組み合わせる**: RFMスコアとLTVの相関を見ることで、より精緻な投資判断が可能になる

### 次のステップ
- **パレート分析**（`/customer` 05）でセグメントごとの売上貢献度を定量化する
- **カスタマージャーニーマップ**（`/customer` 03）で離反リスク顧客の体験を可視化し、離脱原因を特定する
- **目標設定フレームワーク**（`/execution`）でセグメント別KPIを設定し、施策の効果を管理する

## 07. STP
**目的**: 市場をセグメント化（S）し、最も勝てるターゲットを選び（T）、競合と差別化されたポジションを確立する（P）。マーケティング戦略の骨格を決めるフレームワーク

**いつ使うか**: 新規事業の市場参入戦略、既存事業のブランド再構築、競合との差別化が曖昧なとき、ターゲット変更を検討するとき

**テンプレート**:

**Segmentation（市場細分化）**:
| 切り口 | セグメント1 | セグメント2 | セグメント3 |
|-------|-----------|-----------|-----------|
| 地理的 | | | |
| 人口統計的 | | | |
| 心理的 | | | |
| 行動的 | | | |

**Targeting（ターゲット選定）**:
- 選定セグメント:
- 選定理由:
- 市場規模:
- 成長性:
- 競合状況:
- 自社の強みとの適合度:

**ターゲティング戦略の種類**:
| 戦略 | 説明 | 適用場面 |
|------|------|---------|
| 無差別型 | 全市場に同一の製品・メッセージ | コモディティ商品（塩、砂糖など） |
| 差別型 | 複数セグメントにそれぞれ最適化 | 大企業で複数ブランド展開する場合 |
| 集中型 | 1つのセグメントに特化 | リソースの限られたスタートアップ |
| マイクロ | 個人単位でカスタマイズ | D2C、パーソナライズサービス |

**Positioning（ポジショニング）**:
- 差別化ポイント:
- ポジショニングステートメント: 「（ターゲット）にとって、（ブランド）は（カテゴリ）の中で（差別化ポイント）を提供する唯一の存在である。なぜなら（根拠）だからである。」

### 記入例（プレミアムドッグフードブランド）

**Segmentation**:
| 切り口 | セグメント1：健康志向オーナー | セグメント2：コスパ重視オーナー | セグメント3：シニア犬オーナー |
|-------|-------------------------|--------------------------|------------------------|
| 地理的 | 都市部（東京・大阪・名古屋） | 全国 | 全国 |
| 人口統計的 | 20〜40代、世帯年収600万以上、DINKS or 子なし | 全年代、世帯年収問わず | 40〜60代、持ち家 |
| 心理的 | 犬を家族同然と考える。オーガニック・無添加にこだわる | 「安くて十分な品質」を求める | 愛犬の健康寿命を延ばしたい |
| 行動的 | 月1万円以上をペット関連に支出。SNSで情報収集 | ホームセンターで購入。価格比較する | 獣医師の推奨を重視。定期購入を好む |

**Targeting**:
- 選定セグメント: セグメント1「健康志向オーナー」
- 選定理由: 高単価・高リピート率が見込める。自社のオーガニック原材料の調達力が強みになる
- 市場規模: 約800億円（プレミアムペットフード市場）
- 成長性: 年率8%成長（ペットの家族化トレンド）
- 競合状況: 大手は低〜中価格帯に集中。プレミアム帯は輸入ブランドが中心で国産ブランドが少ない
- 自社の強みとの適合度: 国産オーガニック原材料の独自調達網を持つ。獣医師監修の配合技術がある

**Positioning**:
- 差別化ポイント: 「国産オーガニック原材料100%・獣医師監修」
- ポジショニングステートメント: 「愛犬の健康に本気でこだわる都市部のオーナーにとって、当ブランドはプレミアムドッグフードの中で、国産オーガニック原材料100%と獣医師監修の栄養設計を両立する唯一の存在である。なぜなら、国内30の有機農家と直接契約し、動物栄養学の専門家チームが全レシピを設計しているからである。」

### よくある失敗
1. **セグメンテーションが人口統計だけ**: 「30代女性」のような属性だけの区分では行動や心理の違いを捉えられない。必ず心理的・行動的変数を組み合わせる
2. **ターゲットを「みんな」にする**: 「幅広い層に愛される」は戦略ではない。捨てるセグメントを決める勇気が重要
3. **ポジショニングが顧客不在**: 「当社は技術力No.1」は自社視点。ポジショニングは「顧客にとってどんな存在か」を定義するもの

### 活用のヒント
- **ポジショニングマップを描く**: 顧客が重視する2軸（例：価格×品質、手軽さ×専門性）でマップを作り、自社と競合をプロットする。空白地帯が機会
- **実際に宣言テストする**: ポジショニングステートメントを5〜10人のターゲット顧客に見せて、「自分向けだ」と感じるか検証する
- **4Pとの一貫性を確認**: STPで決めたポジショニングが、Price・Product・Place・Promotionと矛盾していないか確認する

### 次のステップ
- **ペルソナ**（`/customer` 01）で選定ターゲットの具体的な人物像を描く
- **TAM/SAM/SOM**（`/customer` 08）で選定セグメントの市場規模を定量化する
- **マクロ環境・業界分析**（`/market`）で市場の魅力度を検証する
- **戦略フレームワーク**（`/strategy`）で4P/4C等のマーケティングミックスを設計する

## 08. TAM／SAM／SOM
**目的**: 市場規模を3段階で推計し、事業の成長ポテンシャルを定量化する。投資判断や事業計画の根拠となる数字を作る

**いつ使うか**: 事業計画書の作成、投資家向けピッチ資料、新規事業のGo/No-Go判断、予算策定の根拠づくり

**テンプレート**:
| レベル | 定義 | 推計値 | 算出根拠 |
|-------|------|-------|---------|
| **TAM**（Total Addressable Market） | 獲得可能な最大市場規模 | | |
| **SAM**（Serviceable Available Market） | 自社がアプローチ可能な市場規模 | | |
| **SOM**（Serviceable Obtainable Market） | 実際に獲得見込みの市場規模 | | |

**推計アプローチ**:
| 手法 | 説明 | メリット | デメリット |
|------|------|---------|----------|
| トップダウン | 市場全体→条件で絞り込み | 早い、マクロ視点 | 楽観的になりがち |
| ボトムアップ | 単価×顧客数×頻度で積み上げ | 現実的、説得力あり | 時間がかかる |
| バリューセオリー | 提供する価値から逆算 | 新市場創造に有効 | 前例がなく検証困難 |

### 記入例（法人向けAI議事録作成SaaS）

**トップダウン推計**:
| レベル | 定義 | 推計値 | 算出根拠 |
|-------|------|-------|---------|
| **TAM** | 世界のAI議事録・会議支援市場 | 5,000億円 | グローバル会議テック市場のうちAI議事録関連。調査会社レポート（2025年）参照 |
| **SAM** | 日本国内の従業員100名以上企業向けAI議事録市場 | 800億円 | 国内企業数約5万社×平均年額160万円（100名×月額1,333円） |
| **SOM** | サービス開始3年以内の獲得見込み | 40億円 | SAMの5%（2,500社）。類似SaaSの初期普及率から推計。営業体制10名で年間800社アプローチ、成約率10%、3年累積 |

**ボトムアップ推計（SOMの検証）**:
- 月額単価: 1ユーザー1,333円（年間16,000円）
- 初年度目標顧客数: 300社（平均100ユーザー/社）
- 初年度売上: 300社 × 100人 × 16,000円 = 4.8億円
- 3年目想定: 顧客数2,500社、年間売上40億円（SOMと整合）

### よくある失敗
1. **TAMを巨大に見せすぎる**: 「日本のIT市場は○兆円」のように上位概念を持ってきて、自社の事業と関係ない部分まで含めてしまう。TAMは「自社製品が理論上すべて置き換わった場合」の市場規模
2. **SOMに根拠がない**: 「シェア5%は取れるはず」の「はず」に説得力がない。営業人数、成約率、マーケティング予算など具体的なリソースから逆算する
3. **一度算出して更新しない**: 市場は変動する。四半期ごとに実績データとの乖離を確認し、推計を修正する

### 活用のヒント
- **必ずトップダウンとボトムアップの両方で検証**: 両者の数値が大きく乖離する場合、仮定のどこかに問題がある
- **出典を明記する**: 調査会社のレポート、政府統計、業界団体のデータなど、第三者データで裏付ける
- **SAM→SOMの転換率を複数シナリオで示す**: 楽観・基本・保守の3パターンで推計すると、投資家やステークホルダーに信頼される
- **競合のシェアから逆算**: 上場している競合の売上高から市場シェアを推計し、自社の目標シェアの妥当性を検証する
- **TAMの成長率も示す**: 静的な数字だけでなく、年率何%で成長しているかを示すことで、市場の魅力度が伝わる

### 次のステップ
- **STP**（`/customer` 07）でSAMのセグメント選定根拠を補強する
- **マクロ環境・業界分析**（`/market`）でTAMの成長要因やリスクを分析する
- **戦略フレームワーク**（`/strategy`）で事業モデルやユニットエコノミクスを設計する
- **目標設定フレームワーク**（`/execution`）でSOM達成のためのマイルストーンを設定する

## 対話の進め方

### ステップ1: ヒアリング
ユーザーの入力内容を確認し、以下の情報を把握する。不足している場合は質問して補う。

- **対象事業**: どんな商品・サービスか。B2B or B2Cか
- **現在のフェーズ**: アイデア段階/MVP検証中/グロース期/成熟期
- **目的**: 新規顧客の獲得/既存顧客の深耕/市場規模の推計/ターゲット変更/離反防止 など
- **利用可能なデータ**: 顧客データベース/アンケート結果/インタビュー記録/売上データ/アクセスログ など
- **アウトプットの用途**: 社内検討用/経営会議資料/投資家向けピッチ/マーケティング施策立案 など

### ステップ2: フレームワーク選定
目的に応じて最適なフレームワークを提案する。以下の対応表を参考にする。

| 目的 | 推奨フレームワーク | 補助フレームワーク |
|------|-----------------|-----------------|
| 顧客像を明確にしたい | ペルソナ（01） | 共感マップ（02） |
| 顧客の本当のニーズを知りたい | ジョブ理論（04） | 共感マップ（02） |
| サービス体験を改善したい | カスタマージャーニー（03） | 共感マップ（02） |
| 顧客に優先順位をつけたい | RFM分析（06） | パレート分析（05） |
| ターゲットを定めたい | STP（07） | ペルソナ（01） |
| 市場規模を知りたい | TAM/SAM/SOM（08） | STP（07） |
| 売上構成を最適化したい | パレート分析（05） | RFM分析（06） |

複数のフレームワークを組み合わせる場合は、上記の順序で進めることを推奨する。

### ステップ3: 対話的にテンプレートを埋める
- 一度にすべての項目を聞かない。3〜4項目ずつ段階的に質問する
- ユーザーの回答に対して「なぜ？」「具体的には？」とフォローアップし、深掘りする
- データがない項目は仮説として記入し、「要検証」とマークする
- ユーザーが詰まっている場合は、業界の一般的な傾向や他社事例を示してヒントを出す

### ステップ4: 完成・出力
- 完成したワークシートをMarkdownで出力する
- 分析結果から導かれる示唆（So What?）を3〜5点述べる
- 次に取り組むべきアクション（Next Steps）を具体的に提案する
- 必要に応じて、関連する他のフレームワーク（`/strategy`、`/market`、`/problem`、`/idea`、`/execution` など）の活用を提案する

### ステップ5: 検証と改善
- 仮説として記入した項目について、検証方法を提案する（インタビュー設計、アンケート項目など）
- 定期的な更新サイクル（月次/四半期/半期）を提案する
- 分析結果の共有先と活用場面を整理する
