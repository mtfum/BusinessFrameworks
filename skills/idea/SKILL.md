# アイデア発想・評価フレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。

## フレームワーク選択ガイド

| 目的 | 推奨フレームワーク |
|------|----------------|
| とにかく大量にアイデアを出したい | ブレインライティング、マンダラート |
| 既存の製品・サービスを改良したい | オズボーンのチェックリスト、SCAMPER |
| 体系的に新しい組み合わせを見つけたい | 形態分析法 |
| ユーザー視点で課題を解決したい | デザイン思考、ストーリーボード |
| アイデアを絞り込み・評価したい | プロコン表、ペイオフマトリクス |

## 01. ブレインライティング

**目的**: 沈黙のブレインストーミング。書くことでアイデアを量産し、他者のアイデアに便乗する

**いつ使うか**: 
- 会議で発言力のある人に場が支配されがちなとき
- 短時間で大量のアイデアが必要なとき
- 1人でブレストの効果を得たいとき（AIが他者の役割を担う）

**テンプレート**（6-3-5法）:
| ラウンド | アイデア1 | アイデア2 | アイデア3 |
|---------|---------|---------|---------|
| 1（最初の発想） | | | |
| 2（前の人に便乗） | | | |
| 3（さらに発展） | | | |
| 4（異なる角度から） | | | |
| 5（統合・飛躍） | | | |
| 6（最終発展） | | | |

**使い方**: 1人でも使える。ラウンドごとに前のアイデアを発展・結合させる。質より量を重視する。

### 記入例（テーマ：「社内コミュニケーション改善」）

| ラウンド | アイデア1 | アイデア2 | アイデア3 |
|---------|---------|---------|---------|
| 1 | 週1回の雑談タイム設置 | 部署横断ランチ制度 | 社内SNSの導入 |
| 2 | 雑談タイムをオンラインでも参加可能に | ランチ代を会社が補助 | SNSに「今日の発見」チャンネル |
| 3 | AIがランダムにペアを組む雑談マッチング | 他部署の人と月1回1on1ランチ義務化 | 週間ベスト投稿を全社会議で紹介 |
| 4 | 経営層も雑談マッチングに参加 | ランチで出たアイデアを提案制度に直結 | 投稿にリアクションした人もポイント付与 |
| 5 | 雑談から生まれたアイデアの実現支援制度 | 「食」をテーマにした部門間プロジェクト | ポイントを研修費用に交換可能に |
| 6 | 全施策を統合した「つながり推進プログラム」 | 四半期ごとの成果発表会 | 外部企業との交流にも拡大 |

### よくある失敗
1. **最初から質を求めてしまう**: ラウンド1で「これは実現可能か？」と考え始めると量が出ない。最初の3ラウンドは判断を完全に保留する
2. **前のアイデアを無視して新規発想ばかりする**: 便乗・発展がこのメソッドの核心。前のラウンドのアイデアを必ず読んでから書く
3. **抽象的なアイデアばかり書く**: 「コミュニケーション向上」のような抽象語ではなく、「月曜10時に15分間の雑談タイム」のように具体的に書く

### 活用のヒント
- ラウンド1〜3は「拡散」、ラウンド4〜6は「深化・統合」と意識する
- 1人で行う場合、ラウンドごとに5分間のインターバルを置くと視点が変わりやすい
- 出たアイデアは最後にKJ法的にグルーピングすると整理しやすい
- 「量が質を生む」を信じて、最低でも各ラウンド3つは必ず埋める

### 次のステップ
- 出たアイデアの優先順位付け → **ペイオフマトリクス**（本スキル09）
- アイデアの賛否を整理 → **プロコン表**（本スキル08）
- アイデアを実行計画に落とす → `/execution`（目標設定・実行管理）
- アイデアの市場性を検証 → `/market`（マクロ環境・業界分析）

## 02. マンダラート

**目的**: 中心テーマから8方向にアイデアを展開し、81マスで思考を広げる

**いつ使うか**:
- 目標を具体的な行動レベルまで分解したいとき
- テーマについて網羅的に考えたいとき
- 思考の抜け漏れをなくしたいとき

**テンプレート**:
```
┌───┬───┬───┐
│   │   │   │
├───┼───┼───┤
│   │中心│   │
├───┼───┼───┤
│   │   │   │
└───┴───┴───┘
```
1. 中心にテーマを置く
2. 周囲8マスに関連要素を書く
3. 各要素を新たな中心として、さらに8マスを展開（合計81マス）

### 記入例（テーマ：「新規事業で年間売上1億円達成」）

**中心の3x3マス**:
```
┌──────────┬──────────┬──────────┐
│ 顧客開拓  │ 商品力強化 │ チーム構築 │
├──────────┼──────────┼──────────┤
│ 資金確保  │ 売上1億  │ 営業戦略  │
├──────────┼──────────┼──────────┤
│ 業務効率化 │ ブランド  │ パートナー │
└──────────┴──────────┴──────────┘
```

**展開例（「顧客開拓」を中心にした3x3）**:
```
┌──────────┬──────────┬──────────┐
│ 展示会出展 │ 紹介制度  │ SNS発信  │
├──────────┼──────────┼──────────┤
│ セミナー  │ 顧客開拓  │ DM送付   │
├──────────┼──────────┼──────────┤
│ Web広告  │ 業界団体  │ 既存顧客深耕│
└──────────┴──────────┴──────────┘
```

**展開例（「商品力強化」を中心にした3x3）**:
```
┌──────────┬──────────┬──────────┐
│ 顧客調査  │ 競合分析  │ 機能追加  │
├──────────┼──────────┼──────────┤
│ UI改善   │ 商品力強化 │ 価格見直し │
├──────────┼──────────┼──────────┤
│ サポート充実│ 導入事例  │ API連携  │
└──────────┴──────────┴──────────┘
```

### よくある失敗
1. **中心テーマが曖昧すぎる**: 「ビジネスを良くする」ではなく「新規事業で年間売上1億円達成」のように測定可能な目標にする
2. **8要素の粒度がバラバラ**: 「マーケティング」と「名刺を作る」が同じレベルに並ぶと展開が困難になる。同じ抽象度で揃える
3. **展開時に中心要素と無関係な項目を書く**: 各3x3マスは中心要素に直結する内容にする。関連が薄いものは別の要素の展開に回す

### 活用のヒント
- 大谷翔平選手の使い方：目標（ドラ1 8球団）→ 8つの要素 → 各要素の具体的行動で目標達成のロードマップを作成
- 8マスが埋まらない場合、そのテーマについての理解が浅い証拠。リサーチの必要性を示すサインと捉える
- 完成後、81マスの中から「最もインパクトが大きく、すぐ着手できるもの」を3つ選んで最初のアクションにする
- 定期的（月1回など）に見直し、進捗を確認・更新すると効果的

### 次のステップ
- 81マスから優先順位を決める → **ペイオフマトリクス**（本スキル09）
- 具体的な目標設定に落とす → `/execution`（OKR、SMARTゴールなど）
- 各要素の課題を深掘りする → `/problem`（問題発見・課題定義）
- 戦略全体を設計する → `/strategy`（戦略立案・ビジネスモデル設計）

## 03. 形態分析法

**目的**: 要素を分解し、その組み合わせから新たなアイデアを体系的に生み出す

**いつ使うか**:
- 新製品・新サービスのコンセプトを網羅的に探索したいとき
- 「ありそうでなかった」組み合わせを発見したいとき
- 直感に頼らず、論理的にアイデアを生成したいとき

**テンプレート**:
| パラメータ | 選択肢A | 選択肢B | 選択肢C | 選択肢D |
|----------|--------|--------|--------|--------|
| 軸1（例：対象） | | | | |
| 軸2（例：場所） | | | | |
| 軸3（例：方法） | | | | |
| 軸4（例：時間） | | | | |

**アイデア**: 各軸から1つずつ選んで組み合わせる → 組合せ総数 = 各軸の選択肢数の積

### 記入例（テーマ：「新しい飲食サービスの開発」）

| パラメータ | 選択肢A | 選択肢B | 選択肢C | 選択肢D |
|----------|--------|--------|--------|--------|
| 対象顧客 | 一人暮らし会社員 | 子育て世帯 | 高齢者 | 外国人観光客 |
| 提供方法 | デリバリー | サブスク定期便 | 自動販売機 | ポップアップ出店 |
| 料理ジャンル | 健康食 | 郷土料理 | スイーツ | 発酵食品 |
| 価格帯 | ワンコイン（500円以下） | 1,000円前後 | プレミアム（3,000円〜） | 従量課金 |

**組み合わせの総数**: 4 x 4 x 4 x 4 = 256通り

**有望な組み合わせ例**:
- 「高齢者 × サブスク定期便 × 健康食 × 1,000円前後」→ 高齢者向け健康食の週3回定期配送
- 「外国人観光客 × 自動販売機 × 郷土料理 × ワンコイン」→ 観光地の郷土料理自販機
- 「一人暮らし会社員 × サブスク定期便 × 発酵食品 × 従量課金」→ 腸活サブスク（食べた分だけ課金）

### よくある失敗
1. **軸の選び方が偏っている**: すべて「モノ」に関する軸だと、サービスやビジネスモデルの革新が出にくい。「誰に」「どこで」「いつ」「どうやって」「いくらで」など多様な視点を入れる
2. **組み合わせを全部検討しようとする**: 256通りすべてを見る必要はない。明らかに不適切な組み合わせは除外し、「意外性のある組み合わせ」に注目する
3. **選択肢が常識的すぎる**: 各軸に1つは「ありえない」と思う選択肢を入れると、破壊的イノベーションのヒントが生まれやすい

### 活用のヒント
- 軸は3〜5本が扱いやすい。6本以上になると組み合わせが膨大になりすぎる
- 最初にランダムに5つの組み合わせを選び、「これは面白い」と感じるものがあるか確認する
- 組み合わせた結果を1行のコンセプト文にまとめる練習をすると、ビジネスアイデアとして磨かれる
- 「この組み合わせが存在しない理由」を考えると、参入障壁や課題が見える

### 次のステップ
- 有望な組み合わせの市場性を検証 → `/market`（マクロ環境・業界分析）
- 顧客ニーズとの適合を確認 → `/customer`（顧客理解・市場セグメント）
- アイデアをさらに発展 → **SCAMPER**（本スキル05）
- 事業としての実現可能性を評価 → `/strategy`（ビジネスモデルキャンバスなど）

## 04. オズボーンのチェックリスト

**目的**: 9つの視点で既存のアイデアや製品を変形・発展させる

**いつ使うか**:
- 既存の製品・サービスの改良案が欲しいとき
- 「もう少し何か違うものにしたい」が、方向性が見えないとき
- 発想の行き詰まりを打破したいとき

**テンプレート**:
| 視点 | 問い | アイデア |
|------|-----|--------|
| 転用（Other uses） | 他に使い道はないか？ | |
| 応用（Adapt） | 他からアイデアを借りられないか？ | |
| 変更（Modify） | 色・形・意味を変えたら？ | |
| 拡大（Magnify） | 大きく・多く・強くしたら？ | |
| 縮小（Minify） | 小さく・少なく・軽くしたら？ | |
| 代用（Substitute） | 他のもので代用できないか？ | |
| 再配置（Rearrange） | 順序・配置を変えたら？ | |
| 逆転（Reverse） | 逆にしたら？上下・前後を入れ替えたら？ | |
| 結合（Combine） | 組み合わせたら？混ぜたら？ | |

### 記入例（対象：「紙の名刺」）

| 視点 | 問い | アイデア |
|------|-----|--------|
| 転用 | 名刺を他に使えないか？ | 名刺がそのままクーポン券になる、QRコードで自己紹介動画に飛ぶ |
| 応用 | 他業界から借りられないか？ | トレーディングカードのように集めたくなるデザイン、ARで3Dモデル表示 |
| 変更 | 形や素材を変えたら？ | 木製名刺、丸型名刺、香り付き名刺 |
| 拡大 | 大きくしたら？ | A4サイズのポートフォリオ付き名刺、名刺がそのままパンフレット |
| 縮小 | 小さくしたら？ | NFCチップ内蔵のピンバッジ型名刺、スマホのウィジェット名刺 |
| 代用 | 他のもので代えられないか？ | 名刺の代わりにLINE交換、ブロックチェーン上のデジタル名刺 |
| 再配置 | 順序を変えたら？ | 名刺交換を会の最後にする（会話後に渡すと記憶に残る） |
| 逆転 | 逆にしたら？ | 相手に自分の情報を書いてもらう「逆名刺」、名刺をもらわない主義 |
| 結合 | 組み合わせたら？ | 名刺＋スマホスタンド、名刺＋植物の種（育てると思い出す） |

### よくある失敗
1. **1つの視点に1つだけアイデアを出して終わる**: 各視点で最低2〜3個は出す。最初のアイデアは誰でも思いつくもので、2個目以降に独自性が出る
2. **現実的かどうかをすぐ判断する**: チェックリストの段階では「面白いかどうか」だけで判断する。実現可能性の評価は後の工程で行う
3. **対象を曖昧にしたまま始める**: 「サービスを改善したい」ではなく「紙の名刺」のように具体的な対象物を1つに絞る

### 活用のヒント
- 9つの視点すべてを必ず通すことが重要。「この視点は関係ない」と飛ばした視点から意外なアイデアが出ることが多い
- チーム作業では、1人1視点ずつ担当すると効率的
- 出たアイデアを「すぐできる / 時間がかかる」「コスト低 / コスト高」で分類すると次のアクションが見える
- 競合製品に対してこのチェックリストを適用すると、差別化のヒントになる

### 次のステップ
- より体系的に変換を進める → **SCAMPER**（本スキル05）
- アイデアの優先順位付け → **ペイオフマトリクス**（本スキル09）
- ユーザー体験として可視化 → **ストーリーボード**（本スキル07）
- 改善案を業務プロセスに組み込む → `/improvement`（業務改善・プロセス最適化）

## 05. SCAMPER

**目的**: オズボーンのチェックリストを発展させた7つの変換技法。より構造化されたアプローチでアイデアを変形する

**いつ使うか**:
- 既存製品・サービスのイノベーションを起こしたいとき
- オズボーンのチェックリストをより深く使いたいとき
- 製品開発やサービス改善のワークショップで

**テンプレート**:
| 技法 | 問い | 具体的な質問例 | アイデア |
|------|-----|-------------|--------|
| **S**ubstitute（代用） | 何を置き換えられるか？ | 素材は？プロセスは？人は？場所は？ | |
| **C**ombine（結合） | 何と組み合わせられるか？ | 機能同士は？目的同士は？素材同士は？ | |
| **A**dapt（適応） | 何を真似・応用できるか？ | 他業界では？自然界では？歴史では？ | |
| **M**odify（修正） | 何を変更・強調できるか？ | 大きさは？色は？形は？速さは？ | |
| **P**ut to other uses（転用） | 別の用途に使えないか？ | 別の顧客は？別の市場は？副産物は？ | |
| **E**liminate（排除） | 何を取り除けるか？ | 不要な機能は？工程は？ルールは？ | |
| **R**earrange/Reverse（再配置/逆転） | 逆にしたら？並び替えたら？ | 順序は？因果は？役割は？ | |

### 記入例（対象：「従来型のフィットネスジム」）

| 技法 | 問い | アイデア |
|------|-----|--------|
| Substitute | トレーナーをAIに置き換えたら？ | AI姿勢分析カメラ＋自動フォーム修正指示。人件費1/3で24時間対応 |
| Combine | ジム×コワーキングスペースは？ | デスクワーク30分→運動15分のサイクルを組み込んだ「動くオフィス」 |
| Adapt | ゲーム業界の仕組みを応用したら？ | RPG型フィットネス：運動で経験値が貯まり、キャラが成長。ギルド（チーム）で協力クエスト |
| Modify | 1回のセッションを極端に短くしたら？ | 7分間HIIT専門ジム。着替え不要、靴のまま。駅ナカに設置 |
| Put to other uses | ジムの設備を別の用途に使えないか？ | 夜間はリハビリ施設として高齢者に開放。昼はアスリート、夜は介護予防 |
| Eliminate | 会員制度をなくしたら？ | 完全従量課金。1分単位で課金。使った分だけ払う |
| Rearrange | 「ジムに行く」を逆にしたら？ | ジムが来る：トレーニング器具を載せたバンが自宅前に来る出張ジム |

### よくある失敗
1. **SCAMPERを順番通りにしか使わない**: 順番は自由。最も刺激的な視点から始めてもよい。むしろ「E（排除）」から始めると本質が見えやすい
2. **1技法につき1アイデアで満足する**: 各技法で最低2つ、できれば3つ以上のアイデアを出す。最初の1つは「普通」であることが多い
3. **対象が大きすぎる**: 「会社全体」ではなく「受付プロセス」「月額課金モデル」など、具体的な要素にフォーカスする

### 活用のヒント
- **E（排除）が最も強力**: 「これを取り除いたらどうなる？」は破壊的イノベーションの起点になりやすい（例：Uber = タクシーから車両所有を排除）
- 7つの技法で出たアイデアを掛け合わせると、さらに独自性が高まる
- 競合のサービスにSCAMPERを適用すると、差別化戦略のヒントが得られる
- 定期的に（四半期ごとなど）自社サービスにSCAMPERを適用する習慣を持つと、継続的イノベーションにつながる

### 次のステップ
- アイデアをユーザー体験に落とし込む → **デザイン思考**（本スキル06）
- アイデアの実現可能性を評価 → **ペイオフマトリクス**（本スキル09）
- 顧客ニーズとの適合確認 → `/customer`（顧客理解・市場セグメント）
- ビジネスモデルの設計 → `/strategy`（ビジネスモデルキャンバスなど）

## 06. デザイン思考（5ステップ）

**目的**: 人間中心のアプローチで課題を発見し、プロトタイプで素早く検証する

**いつ使うか**:
- ユーザーの本当の課題がわからないとき
- 技術ドリブンではなく、ニーズドリブンで考えたいとき
- 早い段階でアイデアの妥当性を検証したいとき
- 新規サービス・プロダクトの初期構想段階

**テンプレート**:
| ステップ | 内容 | アウトプット |
|---------|------|-----------|
| 1. **共感（Empathize）** | ユーザーの観察・インタビュー | インサイト・気づき |
| 2. **問題定義（Define）** | 真の課題を特定 | POV（視点）ステートメント |
| 3. **発想（Ideate）** | アイデアを大量に出す | アイデアリスト |
| 4. **試作（Prototype）** | 素早く形にする | プロトタイプ |
| 5. **検証（Test）** | ユーザーに試してもらう | フィードバック・改善点 |

**POVステートメント**: 「（ユーザー）は（ニーズ）を必要としている。なぜなら（インサイト）だから」

### 記入例（テーマ：「病院の待ち時間問題」）

| ステップ | 内容 | アウトプット |
|---------|------|-----------|
| 共感 | 患者20名にインタビュー。待合室での行動観察。受付スタッフへのヒアリング | 患者は「待ち時間の長さ」より「あとどれくらい待つかわからない不安」がストレス。高齢者は「座る場所」の確保にも苦労 |
| 問題定義 | 不安の根源は「情報不足」と「時間の無駄遣い感」 | 「通院患者は、待ち時間を有意義に使える選択肢を必要としている。なぜなら、不確実な待ち時間が無力感とストレスを生んでいるから」 |
| 発想 | ブレインライティングで30個のアイデア → 投票で5個に絞り込み | (1)リアルタイム待ち順位表示 (2)外出可能な呼び出しアプリ (3)待ち時間中の健康相談 (4)近隣カフェ提携 (5)オンライン事前問診 |
| 試作 | 紙のモックアップで呼び出しアプリのUIを作成。簡易Webページで待ち順位表示を再現 | スマホ画面3枚のペーパープロト。受付番号を入れると「あと約○分」が表示される最小限の機能 |
| 検証 | 患者10名にプロトを見せてフィードバック | 「時間が見えるだけで安心」「高齢者はスマホが苦手→院内モニター表示も必要」「外出できるなら近くの薬局で先に薬をもらいたい」 |

### よくある失敗
1. **共感ステップを飛ばす**: 「ユーザーの気持ちはわかっている」と思い込んで、いきなり解決策を考え始める。最低5人にはインタビューする
2. **問題定義が解決策になっている**: 「アプリが必要」は問題定義ではなく解決策。「待ち時間の不確実性によるストレス」が問題定義
3. **プロトタイプに時間をかけすぎる**: 完璧を目指さない。紙とペンで30分で作れるもので十分。目的は「学ぶこと」であって「完成品を作ること」ではない

### 活用のヒント
- 5ステップは直線的ではなく反復的。検証で得た学びをもとに共感ステップに戻ることが重要
- 「How Might We（どうすれば〜できるだろうか）」の形式で問題を再定義すると、発想が広がる
- 発想ステップでは本スキルの他のフレームワーク（ブレインライティング、SCAMPER等）を組み合わせる
- プロトタイプは「失敗するために作る」という意識を持つ。失敗から最も多く学べる
- 1サイクルを1〜2週間で回すスピード感が大切

### 次のステップ
- 発想ステップで使う → **ブレインライティング**（本スキル01）、**SCAMPER**（本スキル05）
- ユーザー体験を可視化 → **ストーリーボード**（本スキル07）
- ユーザーを深く理解する → `/customer`（ペルソナ、カスタマージャーニーなど）
- 検証結果を踏まえた戦略策定 → `/strategy`（戦略立案・ビジネスモデル設計）
- 課題の根本原因を分析 → `/problem`（問題発見・課題定義）

## 07. ストーリーボード

**目的**: アイデアやユーザー体験を時系列のビジュアルストーリーとして描く

**いつ使うか**:
- アイデアを他者に伝えたいとき
- ユーザー体験の流れを設計・確認したいとき
- サービスのタッチポイントを洗い出したいとき
- プレゼンテーションで共感を得たいとき

**テンプレート**:
| シーン | 1. きっかけ | 2. 行動 | 3. 体験 | 4. 結果 |
|-------|-----------|--------|--------|--------|
| 状況 | | | | |
| ユーザーの行動 | | | | |
| 感情 | | | | |
| タッチポイント | | | | |

**使い方**: 絵が描けなくてもOK。テキストベースでもシーンの流れを可視化することが重要。

### 記入例（テーマ：「AIチャットボットによるカスタマーサポート」）

| シーン | 1. きっかけ | 2. 最初の接触 | 3. 問題解決 | 4. フォローアップ |
|-------|-----------|------------|-----------|---------------|
| 状況 | 深夜2時、購入した家電が動かない。翌日の来客に間に合わせたい | WebサイトのチャットアイコンをクリックするとAIが「こんばんは」と応答 | AIが症状を聞き取り、リセット手順を案内。画像付きで手順を表示 | 翌朝、「昨晩の件、解決しましたか？」とフォローメールが届く |
| ユーザーの行動 | スマホで「製品名 故障」と検索 → 公式サイトへ | 「電源が入らない」と入力。AIの質問に答える | 手順通りに操作。途中でわからない点を追加質問 | 「解決しました！」と返信。ついでに別の質問も |
| 感情 | 😰 焦り・不安「深夜だからサポートに電話できない」 | 😮 驚き「深夜なのに対応してくれるんだ」 | 😊 安心「わかりやすい。自分で直せそう」 | 😍 感動「ここまでフォローしてくれるのか」 |
| タッチポイント | Google検索 → 公式サイト | チャットウィジェット → AI応答 | チャット画面 → 画像表示 → 動画リンク | フォローメール → チャット履歴 |

### よくある失敗
1. **ハッピーパスしか描かない**: 「うまくいかなかった場合」のシーンも描く。エラー時やユーザーが迷う場面こそサービス設計の腕の見せ所
2. **感情の変化を省略する**: ストーリーボードの核心はユーザーの感情変化。各シーンで感情を明記しないと、単なる手順書になってしまう
3. **シーンが多すぎる/少なすぎる**: 4〜8シーンが適切。多すぎると焦点がぼやけ、少なすぎると体験の流れが見えない

### 活用のヒント
- 「ビフォー・アフター」の2本を作ると、提案の価値が明確に伝わる
- 各シーンに「ここで離脱するリスク」を書き添えると、UX改善のポイントが見える
- ペルソナ（具体的な人物像）を設定してからストーリーを描くとリアリティが増す
- テキストベースで作成後、実際にスケッチや画面モックに発展させるとチーム内の認識が揃いやすい
- 1つのアイデアに対して、異なるペルソナで複数のストーリーボードを作ると、サービスの汎用性が検証できる

### 次のステップ
- ペルソナの設計 → `/customer`（顧客理解・市場セグメント）
- ストーリーの各シーンの課題を分析 → `/problem`（問題発見・課題定義）
- プレゼンテーション用に構造化 → `/communication`（伝達・プレゼンテーション）
- サービスプロセスを改善 → `/improvement`（業務改善・プロセス最適化）

## 08. プロコン表

**目的**: 賛成（Pro）と反対（Con）を並べて意思決定を支援する

**いつ使うか**:
- 重要な意思決定で迷っているとき
- 感情的になりがちな議題を客観的に整理したいとき
- ステークホルダー間で意見が割れているとき
- 複数の選択肢を比較したいとき

**テンプレート**:
**テーマ**: _______________

| Pro（賛成・メリット） | 重要度 | Con（反対・デメリット） | 重要度 |
|-------------------|-------|-------------------|-------|
| | 高/中/低 | | 高/中/低 |
| | 高/中/低 | | 高/中/低 |
| | 高/中/低 | | 高/中/低 |

**判定**: 

### 記入例（テーマ：「フルリモートワーク制度の導入」）

| Pro（賛成・メリット） | 重要度 | Con（反対・デメリット） | 重要度 |
|-------------------|-------|-------------------|-------|
| 通勤時間ゼロ → 社員の可処分時間が平均2時間/日増加 | 高 | 対面でのコミュニケーション機会の減少 | 高 |
| オフィス賃料の削減（年間約3,000万円） | 高 | 新入社員のオンボーディングが困難 | 高 |
| 全国・海外から優秀な人材を採用可能 | 高 | チームの一体感・企業文化の維持が難しい | 中 |
| 育児・介護との両立がしやすく離職率低下 | 中 | 情報セキュリティリスクの増加 | 中 |
| 自然災害時の事業継続性向上 | 中 | 自宅の作業環境が整っていない社員への対応 | 低 |
| 社員の自律性・セルフマネジメント力が向上 | 低 | 労務管理（残業把握等）の複雑化 | 中 |

**判定**: Pro側は「コスト削減」「人材獲得」「離職率低下」の3つが高重要度で経営インパクト大。Con側は「コミュニケーション」「オンボーディング」が高重要度だが、ハイブリッド型（週2出社）で緩和可能。→ **ハイブリッドリモート制度として段階的に導入を推奨**

### よくある失敗
1. **Proばかり（またはConばかり）が多い**: すでに結論が決まっている状態で作ると偏る。意識的に反対側を5つ以上出す努力をする。「悪魔の代弁者」役を設ける
2. **重要度をすべて「高」にしてしまう**: 重要度に差をつけないと判断材料にならない。「この項目がなくても決定は変わるか？」と自問して優先順位をつける
3. **定性的な項目だけで判断する**: 可能な限り数値化する。「コスト削減」→「年間3,000万円削減」のように定量化すると判断精度が上がる

### 活用のヒント
- 重要度に加えて「確実性」も評価すると精度が上がる（確実に起きるCon vs 起きるかわからないPro）
- 複数の選択肢がある場合、選択肢ごとにプロコン表を作り、横並びで比較する
- 「このConを解消する方法はないか？」と考えると、条件付き賛成や段階的導入のアイデアが生まれる
- 決定後もプロコン表を保管し、実際にどうなったかを振り返ると意思決定の質が向上する
- ステークホルダーごとに別々にプロコン表を書いてもらい、突き合わせると認識のギャップが見える

### 次のステップ
- より定量的な評価 → **ペイオフマトリクス**（本スキル09）
- 決定事項の実行計画 → `/execution`（目標設定・実行管理）
- 組織への影響を分析 → `/organization`（組織・チームマネジメント）
- 決定事項を関係者に伝える → `/communication`（伝達・プレゼンテーション）
- Conの根本原因を分析 → `/problem`（問題発見・課題定義）

## 09. ペイオフマトリクス

**目的**: アイデアを「効果」と「実現性（コスト・工数）」の2軸で評価し、優先順位をつける

**いつ使うか**:
- アイデアが多すぎて何から手をつけるべきかわからないとき
- リソース（時間・予算・人員）が限られているとき
- チームで優先順位の合意を取りたいとき
- 四半期計画やスプリントプランニングで

**テンプレート**:
|  | 実現容易 | 実現困難 |
|---|--------|--------|
| **効果：大** | Quick Win（即実行） | 大型プロジェクト（計画的に） |
| **効果：小** | 余裕があれば（Fill-in） | 見送り（Money Pit） |

**アイデア配置**:
- Quick Win:
- 大型プロジェクト:
- 余裕があれば:
- 見送り:

### 記入例（テーマ：「ECサイトの売上改善施策の優先順位付け」）

|  | 実現容易（1ヶ月以内・100万円以下） | 実現困難（3ヶ月以上・500万円以上） |
|---|--------|--------|
| **効果：大**（売上10%以上向上見込み） | **Quick Win** | **大型プロジェクト** |
| **効果：小**（売上5%未満の改善見込み） | **余裕があれば** | **見送り** |

**アイデア配置**:
- **Quick Win（即実行）**:
  - カート放棄メール自動配信（効果：CV率15%改善、工数：2週間）
  - 商品ページのCTAボタン色・位置の最適化（効果：クリック率20%向上、工数：3日）
  - レビュー依頼メールの導入（効果：レビュー数3倍→信頼性向上、工数：1週間）
- **大型プロジェクト（計画的に）**:
  - AIレコメンドエンジンの導入（効果：客単価30%向上、工数：6ヶ月、費用：800万円）
  - モバイルアプリの開発（効果：リピート率2倍、工数：8ヶ月、費用：1,500万円）
- **余裕があれば（Fill-in）**:
  - FAQページの充実（効果：問い合わせ20%削減、工数：2週間）
  - SNSシェアボタンの追加（効果：流入5%増、工数：1日）
- **見送り（Money Pit）**:
  - 全商品の3Dビュー対応（効果：不明、工数：12ヶ月、費用：2,000万円）
  - メタバース上の仮想店舗（効果：話題性のみ、工数：10ヶ月、費用：3,000万円）

### よくある失敗
1. **「効果」と「実現性」の基準が曖昧**: 「大」「小」「容易」「困難」の具体的な閾値を事前に定義する。上記の例のように金額・期間・パーセンテージで線引きする
2. **すべてQuick Winに入れてしまう**: 楽観バイアスに注意。実現性は「最悪のケース」で見積もる。効果は「保守的に」見積もる
3. **配置して終わりにする**: マトリクスは意思決定ツール。配置後に「Quick Winから順に着手」「大型プロジェクトは来期の計画に」等のアクションを決めるところまでがセット

### 活用のヒント
- 2軸それぞれに具体的な数値基準を設定する（例：効果＝売上インパクト、実現性＝工数×コスト）
- チームで行う場合、まず個人で配置してから突き合わせると、認識の違いが浮き彫りになる
- Quick Winは「今週中に着手」、大型プロジェクトは「来月のロードマップに追加」のようにタイムラインも決める
- 四半期ごとに再評価する。技術の進歩や市場変化で「実現困難」が「実現容易」に変わることがある
- 「見送り」は「永久に却下」ではない。「今はやらない」という判断であり、条件が変われば再検討する

### 次のステップ
- Quick Winの実行計画を立てる → `/execution`（目標設定・実行管理）
- 大型プロジェクトの戦略を策定 → `/strategy`（戦略立案・ビジネスモデル設計）
- 実行前に課題を洗い出す → `/problem`（問題発見・課題定義）
- チームの体制を整える → `/organization`（組織・チームマネジメント）
- プロセスの効率化で実現性を上げる → `/improvement`（業務改善・プロセス最適化）

## 対話の進め方

### ステップ1：ヒアリング
ユーザーのテーマ・状況を正確に把握するために、以下を確認する：

1. **テーマの確認**: 「何について考えたいですか？」
2. **目的の確認**: 「新しいアイデアを出したいですか？それとも既にあるアイデアを評価・選別したいですか？」
3. **制約条件の確認**: 「時間・予算・人員などの制約はありますか？」
4. **背景の確認**: 「これまでにどんな検討をされましたか？」
5. **アウトプットの確認**: 「最終的にどんな形でまとめたいですか？（会議資料、提案書、個人の整理など）」

### ステップ2：フレームワーク選定
ヒアリング結果に基づき、最適なフレームワークを提案する：

| ユーザーの状況 | 推奨フレームワーク | 理由 |
|-------------|----------------|------|
| 「アイデアがゼロの状態」 | ブレインライティング or マンダラート | ゼロからの発散に最適 |
| 「既存製品を改良したい」 | オズボーンのチェックリスト or SCAMPER | 既存物の変形・発展に特化 |
| 「新サービスの要素を組み合わせたい」 | 形態分析法 | 体系的な組み合わせ探索 |
| 「ユーザーの課題を解決したい」 | デザイン思考 | 人間中心のアプローチ |
| 「アイデアを人に伝えたい」 | ストーリーボード | 体験の可視化・共有 |
| 「どの案にするか迷っている」 | プロコン表 | 賛否の整理・可視化 |
| 「多数のアイデアに優先順位をつけたい」 | ペイオフマトリクス | 効果×実現性での評価 |

**複数のフレームワークの組み合わせ推奨パターン**:
- **発散→収束**: ブレインライティング → ペイオフマトリクス
- **改良→評価**: SCAMPER → プロコン表
- **探索→可視化→検証**: 形態分析法 → ストーリーボード → デザイン思考
- **目標設定→行動分解**: マンダラート → `/execution`のOKR

### ステップ3：対話的にテンプレートを埋める
- 一度にすべてを埋めようとせず、1セクションずつ対話しながら進める
- ユーザーの回答が抽象的な場合、「具体的には？」「例えば？」と深掘りする
- 行き詰まったら、別の視点を提示する（「逆の立場から考えると？」「5年後にはどうなっていますか？」）
- 適宜、「ここまでの内容を整理しますね」と中間まとめを挟む

### ステップ4：完成・出力
- 完成したワークシートをMarkdownで整形して出力
- 主要な発見・インサイトを3つ以内で要約する
- 次のアクション（何を、いつまでに、誰が）を提案する
- 関連する他のフレームワーク（次のステップ）を提案する

### ステップ5：フォローアップ
- 「この結果をもとに、さらに深掘りしたい部分はありますか？」
- 「他のフレームワークと組み合わせて、さらに検討を進めますか？」
- 必要に応じて、他のスキル（`/strategy`, `/problem`, `/customer`等）への接続を提案する
