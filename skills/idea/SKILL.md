# アイデア発想・評価フレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。

---

## 01. ブレインライティング
**目的**: 沈黙のブレインストーミング。書くことでアイデアを量産し、他者のアイデアに便乗する
**テンプレート**（6-3-5法）:
| ラウンド | アイデア1 | アイデア2 | アイデア3 |
|---------|---------|---------|---------|
| 1（最初の発想） | | | |
| 2（前の人に便乗） | | | |
| 3（さらに発展） | | | |

**使い方**: 1人でも使える。ラウンドごとに前のアイデアを発展・結合させる。質より量を重視する。

---

## 02. マンダラート
**目的**: 中心テーマから8方向にアイデアを展開し、81マスで思考を広げる
**テンプレート**:
```
┌───┬───┬───┐
│   │   │   │
├───┼───┼───┤
│   │中心│   │
├───┼───┼───┤
│   │   │   │
└───┴───┴───┘
```
1. 中心にテーマを置く
2. 周囲8マスに関連要素を書く
3. 各要素を新たな中心として、さらに8マスを展開

**使い方**: 大谷翔平選手の目標設定シートで有名。目標設定にもアイデア発想にも使える。

---

## 03. 形態分析法
**目的**: 要素を分解し、その組み合わせから新たなアイデアを体系的に生み出す
**テンプレート**:
| パラメータ | 選択肢A | 選択肢B | 選択肢C | 選択肢D |
|----------|--------|--------|--------|--------|
| 軸1（例：対象） | | | | |
| 軸2（例：場所） | | | | |
| 軸3（例：方法） | | | | |
| 軸4（例：時間） | | | | |

**アイデア**: 各軸から1つずつ選んで組み合わせる → 組合せ総数 = 各軸の選択肢数の積

## 04. オズボーンのチェックリスト
**目的**: 9つの視点で既存のアイデアや製品を変形・発展させる
**テンプレート**:
| 視点 | 問い | アイデア |
|------|-----|--------|
| 転用（Other uses） | 他に使い道はないか？ | |
| 応用（Adapt） | 他からアイデアを借りられないか？ | |
| 変更（Modify） | 色・形・意味を変えたら？ | |
| 拡大（Magnify） | 大きく・多く・強くしたら？ | |
| 縮小（Minify） | 小さく・少なく・軽くしたら？ | |
| 代用（Substitute） | 他のもので代用できないか？ | |
| 再配置（Rearrange） | 順序・配置を変えたら？ | |
| 逆転（Reverse） | 逆にしたら？上下・前後を入れ替えたら？ | |
| 結合（Combine） | 組み合わせたら？混ぜたら？ | |

---

## 05. SCAMPER
**目的**: オズボーンのチェックリストを発展させた7つの変換技法
**テンプレート**:
| 技法 | 問い | アイデア |
|------|-----|--------|
| **S**ubstitute（代用） | 何を置き換えられるか？ | |
| **C**ombine（結合） | 何と組み合わせられるか？ | |
| **A**dapt（適応） | 何を真似・応用できるか？ | |
| **M**odify（修正） | 何を変更・強調できるか？ | |
| **P**ut to other uses（転用） | 別の用途に使えないか？ | |
| **E**liminate（排除） | 何を取り除けるか？ | |
| **R**earrange/Reverse（再配置/逆転） | 逆にしたら？並び替えたら？ | |

## 06. デザイン思考（5ステップ）
**目的**: 人間中心のアプローチで課題を発見し、プロトタイプで素早く検証する
**テンプレート**:
| ステップ | 内容 | アウトプット |
|---------|------|-----------|
| 1. **共感（Empathize）** | ユーザーの観察・インタビュー | インサイト・気づき |
| 2. **問題定義（Define）** | 真の課題を特定 | POV（視点）ステートメント |
| 3. **発想（Ideate）** | アイデアを大量に出す | アイデアリスト |
| 4. **試作（Prototype）** | 素早く形にする | プロトタイプ |
| 5. **検証（Test）** | ユーザーに試してもらう | フィードバック・改善点 |

**POVステートメント**: 「（ユーザー）は（ニーズ）を必要としている。なぜなら（インサイト）だから」

**使い方**: 絵が描けなくてもOK。テキストベースでもシーンの流れを可視化することが重要。

## 対話の進め方

1. AskUserQuestionでテーマ・制約条件をヒアリング

3. 対話的にテンプレートを埋める
