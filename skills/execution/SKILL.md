# 目標設定・実行管理フレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。

---

## 01. OKR（Objectives and Key Results）
**目的**: 野心的な目標と定量的な成果指標を紐づけて、組織の方向性を揃える
**テンプレート**:
| レベル | Objective（目標） | Key Result 1 | Key Result 2 | Key Result 3 |
|-------|-----------------|-------------|-------------|-------------|
| 全社 | | | | |
| チーム | | | | |
| 個人 | | | | |

**ルール**:
- Objectiveは定性的・挑戦的（ワクワクするもの）
- Key Resultは定量的・測定可能（達成度60-70%が理想的な難易度）
- 四半期ごとに設定・振り返り

## 02. KPIツリー
**目的**: 最終目標（KGI）を因数分解し、各レイヤーのKPIと担当を明確にする
**テンプレート**:
```
KGI: 売上 ○○円
├── KPI: 顧客数 × 客単価
│   ├── KPI: 新規顧客数
│   │   ├── KPI: リード数 × CVR
│   │   └── 担当: マーケティング
│   └── KPI: 既存顧客LTV
│       └── 担当: カスタマーサクセス
└── ...
```

**使い方**: KGIから逆算してツリーを作る。各KPIに担当者とアクションを紐づける。

## 03. SMART
**目的**: 目標を5つの基準で具体化し、実行可能な形にする
**テンプレート**:

|------|---------|------|
| **S**pecific（具体的） | □ | 何を達成するのか？ |
| **M**easurable（測定可能） | □ | どう測るのか？数値は？ |

| **R**elevant（関連性） | □ | 上位目標と整合しているか？ |
| **T**ime-bound（期限付き） | □ | いつまでに？ |

## 04. AARRR（海賊指標）
**目的**: サービスのグロースを5段階のファネルで管理する
**テンプレート**:
| 段階 | 定義 | 現状値 | 目標値 | 主要施策 |
|------|------|-------|-------|---------|
| **A**cquisition（獲得） | ユーザーがサービスを知る | | | |
| **A**ctivation（活性化） | 初回の価値体験 | | | |
| **R**etention（継続） | 繰り返し利用 | | | |
| **R**eferral（紹介） | 他者に薦める | | | |
| **R**evenue（収益） | 課金・収益化 | | | |

**使い方**: まずRetention（継続率）を改善してからAcquisition（獲得）に投資するのが鉄則。

## 05. ロードマップ
**目的**: 中長期の計画をタイムラインで可視化し、マイルストーンを管理する
**テンプレート**:
| 期間 | Q1 | Q2 | Q3 | Q4 |
|------|----|----|----|----|
| テーマ | | | | |
| マイルストーン | | | | |
| 主要タスク | | | | |
| リソース | | | | |
| リスク | | | | |

**使い方**: 詳細すぎるロードマップは陳腐化する。大きなマイルストーンと方向性を示すことに注力する。

## 06. ガントチャート
**目的**: プロジェクトのタスク・担当・期間・依存関係を一覧で管理する
**テンプレート**:
| タスク | 担当 | 開始日 | 終了日 | W1 | W2 | W3 | W4 | 依存 |
|-------|------|-------|-------|----|----|----|----|------|
| | | | | ██ | | | | |
| | | | | | ██ | ██ | | タスク1 |
| | | | | | | ██ | ██ | タスク2 |

**使い方**: クリティカルパス（最長経路）を意識して遅延リスクを管理する。

## 07. バランスト・スコアカード（BSC）
**目的**: 財務だけでなく4つの視点で経営をバランスよく評価・管理する
**テンプレート**:
| 視点 | 戦略目標 | KPI | 目標値 | アクション |
|------|---------|-----|-------|----------|
| **財務** | | | | |
| **顧客** | | | | |
| **業務プロセス** | | | | |
| **学習と成長** | | | | |

**因果関係**: 学習と成長 → 業務プロセス改善 → 顧客満足度向上 → 財務成果

---

## 08. OODAループ
**目的**: 変化の速い環境で素早く意思決定・行動するための思考サイクル
**テンプレート**:
| フェーズ | 内容 | 現状 |
|---------|------|------|
| **O**bserve（観察） | 何が起きているか？生データを収集 | |
| **O**rient（状況判断） | 何を意味するか？文脈の解釈 | |
| **D**ecide（意思決定） | 何をするか？行動方針の決定 | |
| **A**ct（実行） | 実行し、結果を次のObserveに回す | |

**使い方**: PDCAとの違いは「計画」ではなく「観察」から始まること。不確実性が高い状況で有効。

---

## 09. 組織図
**目的**: 組織の構造・指揮命令系統・責任範囲を可視化する
**テンプレート**:
```
            [CEO]
        ┌────┼────┐
      [事業A] [事業B] [管理]
      ┌─┴─┐        ┌─┴─┐
    [開発] [営業]  [人事] [経理]
```

**種類**: 機能別組織、事業部制組織、マトリクス組織、プロジェクト型組織
