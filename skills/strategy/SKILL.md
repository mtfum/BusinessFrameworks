# 戦略立案・ビジネスモデル設計フレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。

---

## フレームワーク選択ガイド

| やりたいこと | 推奨フレームワーク | 補助的に使えるもの |
|---|---|---|
| 複数事業の投資優先度を決めたい | PPM | コア・コンピタンス分析 |
| 成長の方向性を決めたい | アンゾフの成長マトリクス | ポジショニングマップ |
| 競合との差別化ポイントを見つけたい | ポジショニングマップ | ブルーオーシャン戦略、4P分析 |
| 新しい市場を創りたい | ブルーオーシャン戦略 | ポジショニングマップ、BMC |
| ビジネスモデルを設計したい | BMC | スキーム図、4P分析 |
| スタートアップの仮説を検証したい | リーンキャンバス | BMC、AIDMA |
| マーケティング施策を整理したい | 4P分析 | AIDMA、ポジショニングマップ |
| 顧客の購買プロセスを設計したい | AIDMA | 4P分析 |
| 自社の強みを明確にしたい | コア・コンピタンス分析 | アンゾフの成長マトリクス |
| ビジネスの仕組みを関係者に説明したい | スキーム図 | BMC |

### よく使われる組み合わせパターン

- **新規事業立案**: リーンキャンバス → BMC → スキーム図（仮説→モデル設計→仕組みの可視化）
- **既存事業の立て直し**: PPM → コア・コンピタンス分析 → アンゾフの成長マトリクス（現状把握→強み特定→成長方向の決定）
- **差別化戦略の策定**: ポジショニングマップ → ブルーオーシャン戦略 → 4P分析（競合分析→差別化設計→施策具体化）
- **マーケティング設計**: 4P分析 → AIDMA → ポジショニングマップ（施策整理→購買プロセス設計→差別化確認）
- **投資家向けピッチ準備**: リーンキャンバス → スキーム図 → コア・コンピタンス分析（ビジネス概要→仕組み→競争優位性）

## 01. PPM（プロダクト・ポートフォリオ・マネジメント）

**目的**: 事業や製品を「市場成長率」と「相対的市場シェア」の2軸で分類し、資源配分を最適化する

**テンプレート**:
|  | 市場シェア：高 | 市場シェア：低 |
|---|-------------|-------------|
| **成長率：高** | ★花形（Star） | ？問題児（Question Mark） |
| **成長率：低** | 💰金のなる木（Cash Cow） | 🐕負け犬（Dog） |

**事業配置**:
| 事業名 | 市場成長率 | 相対シェア | 象限 | 投資方針 |
|-------|----------|----------|------|---------|
| | | | | |

### いつ使うか
- 複数の事業・製品ラインを持つ企業が、限られた経営資源（予算・人材）をどこに集中させるか判断したいとき
- 年度の投資計画・事業ポートフォリオの見直し時
- 新規事業への投資と既存事業の撤退判断を同時に行いたいとき

### 記入例（総合家電メーカー）
| 事業名 | 市場成長率 | 相対シェア | 象限 | 投資方針 |
|-------|----------|----------|------|---------|
| スマートホーム事業 | 年15%成長 | 0.6（2位） | 問題児 | 選択的投資。シェア拡大の見込みがあれば重点投資、なければ撤退検討 |
| 冷蔵庫事業 | 年1%成長 | 1.8（1位） | 金のなる木 | 現状維持。利益を他事業へ再投資 |
| EV充電器事業 | 年25%成長 | 1.3（1位） | 花形 | 積極投資。シェア維持・拡大 |
| FAX事業 | 年-5%縮小 | 0.4（3位） | 負け犬 | 段階的撤退。残存利益を回収 |

### よくある失敗
- **市場の定義が曖昧**: 「IT事業」のように広すぎる市場定義にすると、成長率やシェアが意味をなさなくなる。事業単位を適切に細分化すること
- **象限だけで機械的に判断する**: 「負け犬＝即撤退」と短絡的に考えがち。負け犬でもシナジーがある場合や、問題児でも投資回収が見込めない場合がある
- **スナップショットで終わる**: 1時点の分析だけでなく、時系列での推移（事業が象限をどう移動しているか）を追うことが重要

### 活用のヒント
- 市場成長率は業界データ（政府統計、調査会社レポート等）を用いて客観的に設定する
- 相対シェアは「自社シェア ÷ 最大競合のシェア」で計算する。1.0以上なら高シェア
- バブルチャートにして事業規模（売上高）を円の大きさで表現すると、経営会議での意思決定が進みやすい
- 3〜5年後の市場成長率予測も併記すると、先手を打った投資判断ができる

### 次のステップ
- 各事業の競争環境を深掘り → **/market**（市場分析）
- 金のなる木の利益で問題児に投資する計画 → **/execution**（実行計画）
- 撤退判断の合意形成 → **/communication**（ステークホルダー説明）
- ポートフォリオ再編後の組織設計 → **/organization**（組織設計）

## 02. アンゾフの成長マトリクス

**目的**: 成長戦略の方向性を「市場」×「製品」の新旧で4パターンに整理する

**テンプレート**:
|  | 既存製品 | 新製品 |
|---|--------|-------|
| **既存市場** | 市場浸透戦略 | 新製品開発戦略 |
| **新市場** | 新市場開拓戦略 | 多角化戦略 |

各象限の具体策:
- 市場浸透:
- 新製品開発:
- 新市場開拓:
- 多角化:

### いつ使うか
- 「次の成長をどこで取るか」を経営層と議論するとき
- 中期経営計画（3〜5年）の方向性を決めるとき
- 既存事業の成長が鈍化し、新たな成長ドライバーを探しているとき

### 記入例（オンライン英会話サービス）
|  | 既存製品（オンライン英会話） | 新製品 |
|---|--------|-------|
| **既存市場（日本の社会人）** | 市場浸透：紹介キャンペーン強化、レッスン頻度向上プラン、法人契約の拡大 | 新製品開発：AIスピーキング練習アプリ、TOEIC対策コース、ビジネス英文添削サービス |
| **新市場** | 新市場開拓：韓国・台湾への展開、小中学生向けジュニアコース、大学向けカリキュラム提供 | 多角化：プログラミング×英語のSTEAM教育、企業向けグローバル人材研修パッケージ |

### よくある失敗
- **すべての象限に手を出す**: リソースが分散し、どれも中途半端になる。優先順位をつけて1〜2象限に集中するのが鉄則
- **市場浸透を軽視する**: 新規事業に目が行きがちだが、既存市場×既存製品の深掘りが最もリスクが低く、多くの企業で伸びしろがある
- **「新」の定義が曖昧**: 「新市場」が本当に自社にとって未経験なのか、隣接領域なのかで難易度が大きく異なる。曖昧なまま進めるとリスク評価を誤る

### 活用のヒント
- 4象限それぞれにリスクレベルを明記する（市場浸透：低、新製品開発：中、新市場開拓：中、多角化：高）
- 各象限で必要なケイパビリティ（技術力、販路、ブランドなど）を併記すると、実現可能性の議論が具体的になる
- 時間軸を加えて「短期は市場浸透、中期は新製品開発、長期は多角化」のようにロードマップ化する
- 多角化は「関連多角化」と「非関連多角化」に分けて考えると、リスクの粒度が上がる

### 次のステップ
- 新市場の規模や魅力度を調査 → **/market**（市場分析）
- 新製品のアイデア創出 → **/idea**（アイデア発想）
- 自社の強みを活かせる方向性か確認 → **/problem**（課題分析）で現状把握
- 選択した戦略の実行計画 → **/execution**（実行計画）

## 03. ポジショニングマップ

**目的**: 競合との位置関係を2軸のマップで可視化し、差別化ポイントや空白地帯を発見する

**テンプレート**:
```
        軸Y（高）
          ↑
    ●B    |    ●C
          |
──────────┼──────────→ 軸X（高）
          |
    ●A    |    ●自社
          |
        軸Y（低）
```
- 軸X:（例：価格 低→高）
- 軸Y:（例：機能 少→多）
- プロットする企業/製品: 

**使い方**: 軸の選び方が肝。顧客の購買決定要因（KBF）を軸にする。

### いつ使うか
- 新製品・サービスの立ち位置を決めるとき
- 競合との差別化ポイントを社内で共有したいとき
- 既存製品のリポジショニング（ブランド再定義）を検討するとき
- 空白地帯（競合がいないポジション）を探したいとき

### 記入例（プロジェクト管理ツール市場）
```
      機能の豊富さ（高）
          ↑
  ●Jira  |    ●Asana
          |
──────────┼──────────→ 価格（高）
          |
  ●Trello |    ●自社ツール
          |  （シンプル×適正価格で
          |   中小企業に特化）
      機能の豊富さ（低）
```
- 軸X: 価格（低→高）
- 軸Y: 機能の豊富さ（少→多）
- **発見**: 「シンプルかつ適正価格」のゾーンに空白あり。中小企業が求める「使いこなせるツール」として参入余地がある

### よくある失敗
- **自社に都合のよい軸を選ぶ**: 自社が有利に見える軸ではなく、顧客が購買時に重視する要因（KBF）を軸にしないと意味がない
- **軸が相関している**: 例えば「品質」と「価格」は相関が高く、プロットが対角線に並ぶだけで差別化の示唆が出にくい。独立性の高い軸を選ぶ
- **プロットして終わる**: マップを作って満足するのではなく、「空白地帯に参入すべきか」「なぜ空白なのか（需要がないのか、誰も気づいていないのか）」を議論することが本質

### 活用のヒント
- 軸の候補を5〜6個出してから、顧客インタビューやアンケートで「購買決定に最も影響する2要素」に絞る
- 同じ市場でも軸を変えて複数のマップを作ると、多角的に競合環境を理解できる
- 時系列で作ると、競合の動きや市場のトレンドが見える（例：3年前と今のマップを比較）
- 円の大きさでシェアや売上規模を表現すると、情報量が増す

### 次のステップ
- 空白地帯のニーズ検証 → **/customer**（顧客分析）
- 差別化を具体的な施策に落とす → **/execution**（実行計画）
- ブルーオーシャンの可能性を検討 → このスキル内の「04. ブルーオーシャン戦略」
- 競合の詳細分析 → **/market**（市場分析）

## 04. ブルーオーシャン戦略（戦略キャンバス）

**目的**: 競争のない未開拓市場を創造するための差別化と低コストの同時追求

**テンプレート（ERRCグリッド）**:
| アクション | 要素 | 具体策 |
|----------|------|-------|
| **Eliminate**（取り除く） | | |
| **Reduce**（減らす） | | |
| **Raise**（増やす） | | |
| **Create**（付け加える） | | |

**戦略キャンバス**: 競合の価値曲線と自社の新しい価値曲線を比較する

### いつ使うか
- 競合との価格競争に疲弊しているとき（レッドオーシャンからの脱出）
- 業界の常識を疑い、まったく新しい価値提案を設計したいとき
- 「これまでにないカテゴリ」の製品・サービスを作りたいとき

### 記入例（格安フィットネスジム）
| アクション | 要素 | 具体策 |
|----------|------|-------|
| **Eliminate**（取り除く） | プール、スタジオレッスン、タオル貸出 | 大型設備を廃止し、初期投資と運営コストを大幅削減 |
| **Reduce**（減らす） | スタッフ常駐時間、受付対応 | 入退館をICカード化し24時間無人運営。スタッフは清掃・メンテ中心 |
| **Raise**（増やす） | 営業時間、マシン台数 | 24時間365日営業。待ち時間ゼロを実現するマシン密度 |
| **Create**（付け加える） | 月額2,980円の価格帯、アプリでのトレーニング記録 | 業界平均の1/3の価格。アプリ連携で自主トレーニングを支援 |

**戦略キャンバス（価値曲線の比較）**:
```
価値レベル
 高│    ★        ★         ★
   │   / \      / \     ★ /
   │  /   \    /   \   / \/
   │ /     \  /     ★ /
 低│/  ──────\/───────/──────
   └─────────────────────────→
    価格 設備 スタッフ 営業時間 アプリ マシン数
    
    ── 従来型ジム   ★ 格安ジム（自社）
```

### よくある失敗
- **EliminateとCreateだけ考える**: ReduceとRaiseも含めた4アクションのバランスが重要。極端な削減だけでは顧客価値が毀損する
- **顧客不在で発想する**: 業界側の論理で「取り除くもの」を決めがち。顧客が本当に不要と感じているものを取り除くこと
- **模倣されやすい戦略になる**: 価格を下げるだけのブルーオーシャンは模倣が容易。構造的に模倣しにくい仕組み（ネットワーク効果、独自リソースなど）を組み込む

### 活用のヒント
- 戦略キャンバスは必ず「業界標準の価値曲線」と「自社の価値曲線」を並べて描く。差が明確に見えることが重要
- ERRCグリッドは社内ワークショップ形式で、各部門のメンバーと一緒に埋めると多様な視点が入る
- 「ノンカスタマー」（今その業界のサービスを使っていない人）に注目すると、Createの発想が広がる
- 完成したERRCを「一文で言うと何が新しいか」にまとめ、エレベーターピッチにできるか確認する

### 次のステップ
- ノンカスタマーの分析 → **/customer**（顧客分析）
- 新しい価値提案のアイデア発想 → **/idea**（アイデア発想）
- ビジネスモデルへの落とし込み → このスキル内の「05. BMC」
- 具体的な実行ロードマップ → **/execution**（実行計画）

## 05. ビジネスモデル・キャンバス（BMC）

**目的**: ビジネスモデルの全体像を9つのブロックで1枚に可視化する

**テンプレート**:
| ブロック | 内容 |
|---------|-----|
| **KP** 主要パートナー | |
| **KA** 主要活動 | |
| **KR** 主要リソース | |
| **VP** 価値提案 | |
| **CR** 顧客との関係 | |
| **CH** チャネル | |
| **CS** 顧客セグメント | |
| **C$** コスト構造 | |
| **R$** 収益の流れ | |

**使い方**: まずVP（価値提案）とCS（顧客セグメント）を埋め、そこから他のブロックを展開する。

### いつ使うか
- 新規事業のビジネスモデルを設計するとき
- 既存事業のビジネスモデルを可視化し、改善ポイントを見つけたいとき
- 投資家やパートナー候補にビジネスの全体像を説明するとき
- 複数のビジネスモデル案を比較検討するとき

### 記入例（フリマアプリ）
| ブロック | 内容 |
|---------|-----|
| **KP** 主要パートナー | 配送会社（ヤマト運輸、日本郵便）、決済プロバイダ（クレジットカード各社）、本人確認サービス |
| **KA** 主要活動 | プラットフォーム開発・運営、不正取引監視、カスタマーサポート、マーケティング |
| **KR** 主要リソース | アプリ・システム基盤、ユーザーベース（ネットワーク効果）、ブランド信頼性、AIによる価格提案エンジン |
| **VP** 価値提案 | 出品者：不用品を簡単に現金化。購入者：新品より安く欲しいものが手に入る。匿名配送で安心取引 |
| **CR** 顧客との関係 | セルフサービス型（アプリ内完結）、評価制度による信頼構築、チャットサポート |
| **CH** チャネル | スマートフォンアプリ（iOS/Android）、TVCMとSNS広告、口コミ |
| **CS** 顧客セグメント | 出品者：20〜40代女性（ファッション・ベビー用品の処分）、購入者：コスパ重視の幅広い層 |
| **C$** コスト構造 | サーバー・インフラ費、開発人件費、TVCM等のマーケティング費、カスタマーサポート運営費 |
| **R$** 収益の流れ | 販売手数料（売上の10%）、送料差額、プロモーション枠の販売（将来） |

### よくある失敗
- **VP（価値提案）が曖昧**: 「便利なサービス」のような抽象的な表現で終わる。顧客のどんな課題をどう解決するか、具体的に書くこと
- **9ブロック間の整合性がない**: KR（リソース）に書いたものがKA（活動）で使われていない、CH（チャネル）がCS（顧客セグメント）に届かないなど、ブロック間のつながりを確認する
- **コストと収益の解像度が低い**: C$とR$を「なんとなく」で埋めると、ビジネスの成立性が検証できない。主要コスト項目と収益源は具体的な金額感まで踏み込む

### 活用のヒント
- 最初の30分はVPとCSだけに集中する。この2つが定まらないと他のブロックがブレる
- 「この9ブロックのうち、最もリスクが高い（不確実な）ブロックはどれか？」を特定し、そこから仮説検証を始める
- 競合のBMCも作成して並べると、自社の差別化ポイントや弱点が明確になる
- 1つの事業でも顧客セグメントが異なれば、複数のBMCを作る（例：B2B向けとB2C向け）

### 次のステップ
- 価値提案の詳細設計 → **/customer**（顧客分析でジョブ・ペイン・ゲインを深掘り）
- ビジネスの仕組みを図解 → このスキル内の「10. スキーム図」
- 仮説検証を高速に回す → このスキル内の「06. リーンキャンバス」
- マーケティング施策の具体化 → このスキル内の「07. 4P分析」

## 06. リーンキャンバス

**目的**: スタートアップ向けにBMCを簡略化。仮説検証サイクルを高速に回す

**テンプレート**:
| ブロック | 内容 |
|---------|-----|
| **課題**（Top 3） | |
| **顧客セグメント** | |
| **独自の価値提案** | |
| **ソリューション** | |
| **チャネル** | |
| **収益の流れ** | |
| **コスト構造** | |
| **主要指標** | |
| **圧倒的な優位性** | |

**使い方**: BMCとの違いは「課題」「ソリューション」「主要指標」「圧倒的な優位性」が入ること。不確実性の高い段階で使う。

### いつ使うか
- 新規事業やスタートアップのアイデアを最初に整理するとき
- 「これは本当に顧客が求めているのか？」を検証する前の仮説整理段階
- ピボット（事業方向の転換）を検討するとき
- 投資家向けのピッチデックの骨格を作るとき

### 記入例（AIチャットSaaS ― 企業のカスタマーサポート自動化）
| ブロック | 内容 |
|---------|-----|
| **課題**（Top 3） | 1. CS対応コストが人件費の30%を占める 2. 夜間・休日の問い合わせに対応できない 3. 対応品質がオペレーターによりバラつく |
| **顧客セグメント** | EC事業者（月間問い合わせ500件以上）、SaaS企業のCSチーム |
| **独自の価値提案** | 導入30分で自社FAQを学習し、問い合わせの70%を自動応答。人間のオペレーターは複雑な案件に集中できる |
| **ソリューション** | 自社データで微調整済みのAIチャットボット。管理画面から回答精度を確認・改善。有人エスカレーション機能付き |
| **チャネル** | コンテンツマーケティング（事例記事）、SaaS比較サイト掲載、展示会、CS責任者向けウェビナー |
| **収益の流れ** | 月額SaaS料金（問い合わせ件数による従量課金。月5万円〜30万円）、導入サポート費（初期10万円） |
| **コスト構造** | AIインフラ費（GPU/API）、開発チーム人件費（5名）、マーケティング費、カスタマーサクセス人件費 |
| **主要指標** | 自動応答率、顧客満足度（CSAT）、MRR（月次定期収益）、チャーンレート、導入リードタイム |
| **圧倒的な優位性** | 独自の業界特化型学習データセット（EC・SaaS領域の10万件の問い合わせデータで事前学習済み） |

### よくある失敗
- **課題とソリューションが対応していない**: 課題で挙げた3つの問題を、ソリューションがちゃんと解決しているか確認する。ズレていると仮説検証の方向がブレる
- **「圧倒的な優位性」に一般的な強みを書く**: 「技術力が高い」「チームが優秀」は優位性ではない。簡単にコピーできないもの（ネットワーク効果、独自データ、特許、ブランド）を書く
- **主要指標を設定しない**: 何をもって「うまくいっている」と判断するか不明確なまま進めると、ピボットの判断ができなくなる

### 活用のヒント
- 最初は20分以内で埋めること。完璧を目指さず、現時点の「最善の仮説」を書く
- リーンキャンバスは1枚で固定ではない。仮説検証のたびに更新し、バージョン管理する（v1, v2, v3...）
- 「課題」は顧客インタビュー前の仮説。インタビュー後に必ず修正する
- 右側（顧客セグメント、チャネル、収益）と左側（課題、ソリューション、コスト）のバランスを意識する

### 次のステップ
- 課題の検証 → **/customer**（顧客インタビュー設計）
- ソリューションのプロトタイプ検証 → **/idea**（アイデアの具体化）
- PMF達成後のスケール → **/execution**（実行計画）
- 検証結果を踏まえたモデル精緻化 → このスキル内の「05. BMC」
- 数値目標の改善サイクル → **/improvement**（改善・振り返り）

## 07. 4P分析（マーケティング・ミックス）

**目的**: マーケティング施策をProduct・Price・Place・Promotionの4要素で設計する

**テンプレート**:
| 4P | 自社 | 競合A | 競合B |
|----|-----|------|------|
| **Product**（製品・サービス） | | | |
| **Price**（価格・料金体系） | | | |
| **Place**（流通・販売チャネル） | | | |
| **Promotion**（販促・コミュニケーション） | | | |

**使い方**: 4Pは売り手視点。顧客視点の4C（Customer Value, Cost, Convenience, Communication）と対比すると深まる。

### いつ使うか
- 新製品の発売時にマーケティング施策の全体像を整理するとき
- 競合との施策比較をして、自社の強み・弱みを把握したいとき
- マーケティング予算の配分を検討するとき
- 既存製品の売上低下の原因を特定したいとき

### 記入例（コーヒーチェーン）
| 4P | 自社 | スターバックス | コンビニコーヒー |
|----|-----|------|------|
| **Product** | シングルオリジン豆のハンドドリップ。焙煎日を明記。フードは地元パン屋と提携 | 豊富なカスタマイズ、季節限定フラペチーノ、フード充実 | 100円で手軽な淹れたてコーヒー。種類は少ないが安定品質 |
| **Price** | ドリップ450円、ラテ550円（中価格帯だが品質で納得感） | ドリップ390円、ラテ490円〜。カスタマイズで単価UP | ドリップ100円、ラテ150円。圧倒的低価格 |
| **Place** | 駅徒歩3分の路面店3店舗。テイクアウト中心の小型店 | 全国1,800店以上。商業施設・駅近 | 全国55,000店のコンビニ。圧倒的な立地数 |
| **Promotion** | Instagram運用（産地ストーリー発信）、近隣オフィスへのチラシ、スタンプカード | TVCM、SNS、リワードプログラム、UGC活用 | 店頭POP、TVCMとの連動。来店ついで買い |

**4C視点での読み替え**:
| 4P | 4C（顧客視点） | 自社の顧客にとっての意味 |
|----|---|---|
| Product | Customer Value | 「どこの誰が作った豆か分かる安心感と特別感」 |
| Price | Cost | 「毎日飲むには少し高いが、週2回のご褒美としてちょうどよい」 |
| Place | Convenience | 「職場の近くにあるから通勤途中に寄れる」 |
| Promotion | Communication | 「Instagramで産地の話を見て応援したくなる」 |

### よくある失敗
- **4Pをバラバラに考える**: Product（高品質）なのにPrice（低価格）にするなど、4P間の一貫性がないと顧客に混乱を与える
- **Placeを店舗だけで考える**: ECサイト、SNS、アプリ、サブスクリプションなど、デジタルチャネルも含めて設計する
- **Promotionに偏る**: 売上が伸びないとき、広告を増やすことばかり考えがちだが、Product自体の見直しやPrice戦略の変更が必要な場合も多い

### 活用のヒント
- まずProductを徹底的に定義してから、他のPを設計する。プロダクトが曖昧だと他がすべてブレる
- 競合の4Pを埋めるときは、実際に競合の製品を購入・利用してみると解像度が上がる
- 4Pの各項目に「なぜそうするのか（顧客にとっての意味）」を必ず添える
- B2BとB2Cで重点が変わる。B2Bでは特にPlaceとProductの比重が高く、B2CではPromotionの影響が大きい

### 次のステップ
- 各施策の実行スケジュール → **/execution**（実行計画）
- ターゲット顧客の深掘り → **/customer**（顧客分析）
- 購買プロセスに沿った施策設計 → このスキル内の「08. AIDMA」
- 競合との差別化を可視化 → このスキル内の「03. ポジショニングマップ」

## 08. AIDMA

**目的**: 消費者の購買心理プロセスを5段階でモデル化し、各段階の施策を設計する

**テンプレート**:
| 段階 | 顧客の状態 | 施策 | KPI |
|------|----------|------|-----|
| **A**ttention（注意） | 知らない→知る | | |
| **I**nterest（興味） | 知る→興味を持つ | | |
| **D**esire（欲求） | 興味→欲しくなる | | |
| **M**emory（記憶） | 欲しい→覚えている | | |
| **A**ction（行動） | 覚えている→買う | | |

**補足**: デジタル時代にはAISAS（Search, Share）やAISCEAS等の派生モデルも検討する。

### いつ使うか
- 新商品の認知からの購買導線を設計するとき
- 「認知はあるのに購入に至らない」などファネルのどこに課題があるか特定したいとき
- マーケティング施策をカスタマージャーニーに沿って整理したいとき
- 広告・PR・販促の予算配分の根拠を作りたいとき

### 記入例（オーガニック化粧品ブランドの新商品発売）
| 段階 | 顧客の状態 | 施策 | KPI |
|------|----------|------|-----|
| **A**ttention（注意） | 知らない→知る | Instagram広告（肌悩み訴求）、美容系インフルエンサーPR投稿、プレスリリース配信 | 広告インプレッション数: 500万/月、メディア掲載数: 20件 |
| **I**nterest（興味） | 知る→興味を持つ | 成分へのこだわりを伝えるブランドストーリー動画、LP（ビフォーアフター事例）、無料サンプル応募ページ | LP訪問数: 5万/月、サンプル応募数: 3,000件 |
| **D**esire（欲求） | 興味→欲しくなる | 口コミサイトでの高評価獲得、皮膚科医監修のエビデンス発信、初回限定30%OFFクーポン | 口コミ評価: 4.2以上、クーポン発行数: 2,000枚 |
| **M**emory（記憶） | 欲しい→覚えている | リターゲティング広告、LINE公式アカウントで週1回の情報配信、メルマガ（肌ケアTips） | LINE友だち数: 5,000人、メルマガ開封率: 25% |
| **A**ction（行動） | 覚えている→買う | EC限定セット販売、購入導線の簡素化（3ステップ決済）、レビュー投稿でポイント付与 | EC月間売上: 500万円、購入転換率: 3%、レビュー投稿率: 15% |

### よくある失敗
- **Attention（認知）に予算を集中しすぎる**: 認知はあるのにDesire（欲求）やAction（行動）の施策が弱いと、ファネルの途中で離脱する。各段階にバランスよく投資する
- **Memory（記憶）段階を軽視する**: 欲しいと思っても、購買タイミングまでに忘れられてしまうことが多い。リマインド施策は地味だが重要
- **オフラインとオンラインを分断して設計する**: 実際の顧客はWebで調べて店舗で買う（またはその逆）。チャネルを横断した設計が必要

### 活用のヒント
- まず現状のファネルデータ（認知率→興味率→購入率）を数字で把握し、最もドロップが大きい段階に集中投資する
- デジタル商材の場合はAISAS（Attention→Interest→Search→Action→Share）の方が実態に合うことが多い
- 各段階のKPIは「1つのメイン指標＋1〜2のサブ指標」に絞る。指標が多すぎると追いきれない
- 購入後の「Share（共有）」「Repeat（リピート）」まで拡張すると、LTV（顧客生涯価値）向上の施策も設計できる

### 次のステップ
- 各段階の施策を具体的なタスクに分解 → **/execution**（実行計画）
- ターゲット顧客のペルソナを精緻化 → **/customer**（顧客分析）
- 施策の効果測定と改善 → **/improvement**（改善・振り返り）
- プロモーション施策の全体設計 → このスキル内の「07. 4P分析」

## 09. コア・コンピタンス分析

**目的**: 自社の中核的な能力を特定し、それを軸にした戦略を構築する

**テンプレート**:
| 候補となる能力 | 顧客価値への貢献 | 競合との差別化 | 展開可能性 | 評価 |
|-------------|--------------|------------|----------|------|
| | 高/中/低 | 高/中/低 | 高/中/低 | |

**3つの条件**:
1. 顧客に認知される価値を提供できる
2. 競合に模倣されにくい
3. 複数の市場・製品に展開できる

### いつ使うか
- 「自社の本当の強みは何か」を経営チームで言語化したいとき
- 多角化やM&Aの方向性を、自社の強みに基づいて決めたいとき
- 組織再編・リストラの際に「守るべき能力」を特定するとき
- 中期経営計画の柱となる競争優位の源泉を定義するとき

### 記入例（精密機器メーカー）
| 候補となる能力 | 顧客価値への貢献 | 競合との差別化 | 展開可能性 | 評価 |
|-------------|--------------|------------|----------|------|
| ナノレベルの精密加工技術 | 高（製品の小型化・高性能化に直結） | 高（20年の蓄積、特許50件） | 高（医療機器、半導体、自動車に展開可能） | ★コア・コンピタンス |
| グローバルな販売ネットワーク | 中（顧客の利便性向上） | 中（大手競合も同等の網を持つ） | 中（既存チャネルでの横展開は可能） | 重要だがコアではない |
| 迅速なアフターサービス体制 | 高（稼働率保証に直結） | 中（差別化だが模倣可能） | 低（サービス対象機器に依存） | 強みだがコアではない |
| 自社一貫生産（設計→製造→検査） | 高（品質安定性） | 高（外注中心の競合にはない） | 中（新製品にも適用可能） | 準コア・コンピタンス |

**結論**: 「ナノレベルの精密加工技術」がコア・コンピタンス。成長戦略はこの技術を軸に、医療機器市場や半導体装置市場への展開を優先する。

### よくある失敗
- **「強み」と「コア・コンピタンス」を混同する**: 営業力、ブランド、立地などは「強み」であってもコア・コンピタンスの3条件を満たさないことが多い。3条件すべてを満たすものだけがコア・コンピタンス
- **現在の能力だけを見る**: 今は弱くても、投資すればコア・コンピタンスになり得る「萌芽的能力」も視野に入れる
- **組織全体で共有しない**: 経営層だけで分析しても現場に浸透しなければ意味がない。全社的に「我々のコア・コンピタンスはこれだ」と合意することが重要

### 活用のヒント
- 候補は最低5〜8個リストアップしてから、3条件で絞り込む。最初から絞ると視野が狭くなる
- 「この能力がなかったら、顧客は他社に乗り換えるか？」という問いで顧客価値への貢献度を検証する
- 「この能力を模倣するのに何年・いくらかかるか？」で模倣困難性を定量的に評価する
- コア・コンピタンスは時間とともに陳腐化する。3〜5年ごとに再評価すること

### 次のステップ
- コア・コンピタンスを活かした成長戦略 → このスキル内の「02. アンゾフの成長マトリクス」
- 展開先の市場分析 → **/market**（市場分析）
- コア・コンピタンスを支える組織設計 → **/organization**（組織設計）
- 能力強化の実行計画 → **/execution**（実行計画）

## 10. スキーム図

**目的**: ビジネスの仕組み（ヒト・モノ・カネ・情報の流れ）を図示して関係者間の構造を可視化する

**テンプレート**:
```
[プレイヤーA] ──サービス提供──→ [プレイヤーB]
      ↑                            │
      │                            ↓
   対価（手数料）              対価（利用料）
      │                            │
      └─────── [プレイヤーC] ←──────┘
```

**記載要素**: 登場人物（ステークホルダー）、提供価値、金銭の流れ、情報の流れ、契約関係

### いつ使うか
- ビジネスモデルを関係者（投資家、パートナー、社内メンバー）に説明するとき
- プラットフォームビジネスなど、複数のステークホルダーが関わるモデルの構造整理
- 新規事業の提案書・事業計画書に「仕組みの全体図」を入れたいとき
- 契約関係や責任範囲を明確にしたいとき

### 記入例（クラウドソーシング型翻訳プラットフォーム）
```
                    [翻訳者（個人）]
                    /        ↑
           翻訳成果物     報酬（翻訳料の80%）
                  /            ↑
                ↓              │
[依頼企業] ──翻訳依頼──→ [自社プラットフォーム] ←──登録・スキル認定
    │                      │        │
    └──対価（翻訳料）──→   │     品質管理
                           │    （AI校正＋人的レビュー）
                           │
                           ↓
                    [決済代行会社]
                    （手数料3%）
```

**登場人物と役割**:
| プレイヤー | 役割 | 提供するもの | 受け取るもの |
|-----------|------|------------|------------|
| 依頼企業 | 翻訳を依頼する | 翻訳料（1文字10円） | 翻訳成果物 |
| 自社プラットフォーム | マッチング・品質管理 | 翻訳者のアサイン、AI校正 | 手数料（翻訳料の20%） |
| 翻訳者 | 翻訳作業を行う | 翻訳成果物 | 報酬（翻訳料の80%） |
| 決済代行会社 | 決済処理 | 安全な決済インフラ | 決済手数料（3%） |

### よくある失敗
- **矢印の方向や意味が曖昧**: 矢印が何を表すか（お金、サービス、情報、契約）を必ずラベルで明記する。矢印だけの図は読み手によって解釈が異なる
- **ステークホルダーの漏れ**: 規制当局、間接的な受益者、エンドユーザーなどを見落としがち。関係者を網羅的にリストアップしてから図を描く
- **複雑にしすぎる**: 1枚の図に全情報を詰め込むと読めなくなる。概要版（主要な流れのみ）と詳細版（すべての流れ）に分ける

### 活用のヒント
- まずステークホルダーを付箋に書き出し、物理的に並べてから矢印を引くと整理しやすい
- 「モノの流れ」「カネの流れ」「情報の流れ」を色分けすると一目で構造が分かる
- 自社が「どこに位置して、何で収益を得るか」がスキーム図の中で最も重要なポイント
- 将来的に変わりうる部分（例：直接取引への移行、中間プレイヤーの排除）を点線で示すと、戦略的な議論がしやすくなる

### 次のステップ
- 各プレイヤーとの契約・提携の具体化 → **/execution**（実行計画）
- ステークホルダーへの説明資料作成 → **/communication**（プレゼン・報告）
- ビジネスモデル全体の設計・検証 → このスキル内の「05. BMC」
- 収益構造の詳細設計 → **/market**（市場分析で市場規模から収益ポテンシャルを検証）

## 対話の進め方

### 基本フロー

1. AskUserQuestionで事業内容・戦略課題をヒアリング
2. フレームワーク選択ガイド（上記の表）を参照し、最適なフレームワークを提案
3. 対話的にテンプレートを埋めていく
4. 完成したワークシートをMarkdownで出力
5. 次のステップとして関連フレームワークや他スキルへの接続を提案

### ヒアリング時の確認ポイント

| 確認項目 | 質問例 |
|---------|-------|
| 事業フェーズ | 「新規立ち上げですか？既存事業の改善ですか？」 |
| 課題の種類 | 「成長戦略、差別化、マーケティング、ビジネスモデル設計のどれに近いですか？」 |
| アウトプットの用途 | 「社内検討用ですか？投資家向けですか？」 |
| 時間軸 | 「短期（〜1年）、中期（1〜3年）、長期（3年〜）のどれを重視しますか？」 |
| 既存の分析 | 「すでに実施した分析（SWOT、3C、市場調査など）はありますか？」 |

### フレームワーク組み合わせの進め方

1つのフレームワークで完結することは少ない。以下の順序で組み合わせると効果的。

**パターン1: ゼロからの新規事業**
```
/problem（課題発見）→ /customer（顧客理解）→ リーンキャンバス → BMC → スキーム図 → 4P分析 → AIDMA → /execution（実行）
```

**パターン2: 既存事業の競争力強化**
```
/market（市場分析）→ コア・コンピタンス分析 → ポジショニングマップ → ブルーオーシャン戦略 → 4P分析 → /execution（実行）
```

**パターン3: 事業ポートフォリオの再編**
```
PPM → コア・コンピタンス分析 → アンゾフの成長マトリクス → BMC（各事業） → /organization（組織再編）
```

**パターン4: マーケティング戦略の刷新**
```
/customer（顧客分析）→ ポジショニングマップ → 4P分析 → AIDMA → /execution（実行）→ /improvement（効果測定・改善）
```
