# 伝達・プレゼンテーションフレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。

---

## 01. PREP
**目的**: 結論ファーストで論理的に伝えるための話法フレーム
**テンプレート**:
| ステップ | 内容 |
|---------|------|
| **P**oint（結論） | |
| **R**eason（理由） | |
| **E**xample（具体例） | |
| **P**oint（結論の再提示） | |

**使い方**: プレゼン・報告・メール・Slack何でも使える。まず結論を述べ、理由→具体例で補強し、最後にもう一度結論。

---

## 02. TAPS
**目的**: 相手を動かすための説得・提案フレーム
**テンプレート**:
| ステップ | 内容 |
|---------|------|
| **T**o be（あるべき姿） | |
| **A**s is（現状） | |
| **P**roblem（問題） | |
| **S**olution（解決策） | |

**使い方**: 理想→現状→ギャップ（問題）→提案の流れで、相手に「変えなければ」という当事者意識を持たせる。

---

## 03. ピラミッドストラクチャー
**目的**: 主張とその根拠を階層構造で整理し、論理的で説得力のある文章・プレゼンを作る
**テンプレート**:
```
            [主張（メインメッセージ）]
           ／        │        ＼
    [根拠1]      [根拠2]      [根拠3]
    ／    ＼      ／    ＼      ／    ＼
[事実] [事実] [事実] [事実] [事実] [事実]
```

| レベル | 内容 |
|-------|------|
| 主張 | |
| 根拠1 | |
| └ 事実・データ | |
| 根拠2 | |
| └ 事実・データ | |
| 根拠3 | |
| └ 事実・データ | |

**使い方**: トップダウン（結論→根拠）で伝え、ボトムアップ（事実→根拠→結論）で検証する。根拠はMECEに。

---

## 04. エレベーターピッチ
**目的**: 30秒〜1分で事業やアイデアの本質を伝える
**テンプレート**:
| 要素 | 内容 |
|------|------|
| **対象顧客** | （誰）にとって |
| **課題** | （何が）問題で |
| **プロダクト名** | （製品名）は |
| **カテゴリ** | （カテゴリ）であり |
| **主要ベネフィット** | （主な価値）を提供する |
| **競合との違い** | （競合）と異なり |
| **独自の差別化** | （差別化ポイント）が特徴 |

**完成文**: 「______にとって______が課題です。______は______であり、______を提供します。______と異なり、______が特徴です。」

---

## 対話の進め方

1. AskUserQuestionで伝えたい内容・相手・場面をヒアリング
2. 最適なフレームワークを提案
3. 対話的にテンプレートを埋めていく
4. 完成した文章・構成をMarkdownで出力
