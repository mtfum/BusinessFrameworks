# 問題発見・課題定義フレームワーク

ユーザーの $ARGUMENTS に基づき、以下のフレームワークから適切なものを適用してください。引数がなければ状況をヒアリングして提案してください。

---

## 01. As is／To be
**目的**: 現状（As is）と理想（To be）のギャップを明確にし、取り組むべき課題を定義する
**テンプレート**:
| 項目 | As is（現状） | To be（理想） | Gap（差分） |
|------|-------------|-------------|-----------|
| 項目1 | | | |
| 項目2 | | | |
| 項目3 | | | |

**使い方**: まず理想状態を具体的に描き、次に現状を正直に書き出す。両者の差分がそのまま課題になる。

---

## 02. 6W2H
**目的**: 課題や企画を多角的に分解し、抜け漏れなく定義する
**テンプレート**:
- **What**（何を）:
- **Why**（なぜ）:
- **Who**（誰が）:
- **Whom**（誰に）:
- **When**（いつ）:
- **Where**（どこで）:
- **How**（どのように）:
- **How much**（いくらで）:

**使い方**: 曖昧な課題を8つの切り口で分解する。すべてを埋める必要はなく、空欄が「情報不足の箇所」として可視化される。

---

## 03. なぜなぜ分析（5 Whys）
**目的**: 表面的な問題から根本原因にたどり着く
**テンプレート**:
```
問題: _______________
なぜ1: _______________
  なぜ2: _______________
    なぜ3: _______________
      なぜ4: _______________
        なぜ5: _______________
→ 根本原因: _______________
```

**使い方**: 「なぜ？」を最低5回繰り返す。途中で分岐する場合はロジックツリーと併用する。

---

## 04. 特性要因図（フィッシュボーンダイアグラム）
**目的**: 問題の原因を体系的に洗い出す
**テンプレート**:
```
            原因カテゴリA ──┐
            原因カテゴリB ──┤
問題 ◀━━━━━━━━━━━━━━━━━━━━┤
            原因カテゴリC ──┤
            原因カテゴリD ──┘
```
主要カテゴリ例: 人（Man）、方法（Method）、材料（Material）、機械（Machine）、測定（Measurement）、環境（Environment）

**使い方**: まず結果（問題）を右端に置き、大骨→中骨→小骨の順で原因を分解していく。

---

## 05. ロジックツリー
**目的**: 問題や論点をMECEに分解して構造化する
**テンプレート**:
```
テーマ
├── 大分類A
│   ├── 中分類A-1
│   └── 中分類A-2
├── 大分類B
│   ├── 中分類B-1
│   └── 中分類B-2
└── 大分類C
    ├── 中分類C-1
    └── 中分類C-2
```

**種類**: Whatツリー（要素分解）、Whyツリー（原因追究）、Howツリー（問題解決）

---

## 06. MECE
**目的**: 漏れなく・ダブりなく要素を洗い出す思考フレーム
**チェックリスト**:
- [ ] 全体集合を定義したか？
- [ ] 各要素に重複はないか？（Mutually Exclusive）
- [ ] 全体を網羅しているか？（Collectively Exhaustive）
- [ ] 切り口は適切か？（対立軸、プロセス、構成要素など）

**代表的な切り口例**: 時系列、プロセス順、対立概念、3C/4P等の既存フレーム

---

## 07. 緊急度／重要度マトリクス
**目的**: タスクや課題の優先順位を4象限で整理する
**テンプレート**:
|  | 重要度：高 | 重要度：低 |
|---|---------|---------|
| **緊急度：高** | 第1象限：即実行 | 第3象限：委任・効率化 |
| **緊急度：低** | 第2象限：計画的に取組む | 第4象限：削減・排除 |

**使い方**: 第2象限（重要だが緊急でない）に時間を使えているかが生産性の鍵。

---

## 08. 意思決定マトリクス
**目的**: 複数の選択肢を定量的に評価して最善策を選ぶ
**テンプレート**:
| 評価基準 | 重み | 選択肢A | 選択肢B | 選択肢C |
|---------|-----|--------|--------|--------|
| 基準1 | ×○ | 点数 | 点数 | 点数 |
| 基準2 | ×○ | 点数 | 点数 | 点数 |
| 基準3 | ×○ | 点数 | 点数 | 点数 |
| **加重合計** | | **○点** | **○点** | **○点** |

**使い方**: 評価基準と重みを先に決め、その後に各選択肢を採点する。感覚的な判断を構造化できる。

---

## 09. イシューツリー
**目的**: 解くべき問い（イシュー）を分解し、検証可能なサブイシューに落とし込む
**テンプレート**:
```
メインイシュー: ________________？
├── サブイシュー1: ____________？
│   ├── 仮説:
│   └── 検証方法:
├── サブイシュー2: ____________？
│   ├── 仮説:
│   └── 検証方法:
└── サブイシュー3: ____________？
    ├── 仮説:
    └── 検証方法:
```

**使い方**: ロジックツリーと異なり、各ノードが「問い」の形になる。仮説駆動で分析を進める際に有効。

---

## 対話の進め方

1. AskUserQuestionでユーザーの状況と課題をヒアリング
2. 最適なフレームワークを提案（理由付き）
3. テンプレートを提示し、項目ごとに対話的に埋めていく
4. 完成したワークシートをMarkdownで出力
5. 必要に応じて次のステップ（分析→戦略など）を提案
