# Idea generation and evaluation frameworks

Based on the user's $ARGUMENTS, apply the appropriate framework from the list below.

## Framework selection guide

| Goal | Recommended framework |
|------|----------------|
| Generate a large number of ideas fast | Brainwriting, Mandalart |
| Improve an existing product or service | Osborn's Checklist, SCAMPER |
| Find new combinations systematically | Morphological Analysis |
| Solve problems from the user's point of view | Design Thinking, Storyboard |
| Narrow down and evaluate ideas | Pros and Cons Table, Payoff Matrix |

## 01. Brainwriting

**Purpose**: Silent brainstorming. Produce many ideas by writing, and build on other people's ideas

**When to use**: 
- When a few vocal people tend to dominate meetings
- When you need many ideas in a short time
- When you want the benefits of brainstorming alone (the AI plays the role of the other participants)

**Template** (6-3-5 method):
| Round | Idea 1 | Idea 2 | Idea 3 |
|---------|---------|---------|---------|
| 1 (first ideas) | | | |
| 2 (build on the previous person) | | | |
| 3 (develop further) | | | |
| 4 (from a different angle) | | | |
| 5 (combine and leap) | | | |
| 6 (final development) | | | |

**How to use**: Works alone too. In each round, develop and combine the ideas from the previous round. Favor quantity over quality.

### Worked example (theme: "Improving internal communication")

| Round | Idea 1 | Idea 2 | Idea 3 |
|---------|---------|---------|---------|
| 1 | Set up a weekly casual chat time | Cross-department lunch program | Introduce an internal social network |
| 2 | Make chat time joinable online too | Company subsidizes lunch costs | Add a "today's discovery" channel to the social network |
| 3 | AI randomly pairs people for chat matching | Mandatory monthly 1-on-1 lunch with someone from another department | Present the best post of the week at the all-hands meeting |
| 4 | Executives also join chat matching | Link ideas from lunches directly to the proposal system | Give points to people who react to posts too |
| 5 | Support program to realize ideas born from chats | Cross-department project on the theme of "food" | Points exchangeable for training costs |
| 6 | "Connection promotion program" that integrates all measures | Quarterly results presentation | Expand to exchanges with outside companies |

### Common mistakes
1. **Demanding quality from the start**: If you start asking "is this feasible?" in round 1, quantity drops. Suspend judgment completely for the first 3 rounds
2. **Ignoring previous ideas and only writing new ones**: Building on and developing ideas is the core of this method. Always read the previous round's ideas before writing
3. **Writing only abstract ideas**: Not abstract phrases like "improve communication" but concrete ones like "15-minute chat time on Mondays at 10:00"

### Tips
- Treat rounds 1 to 3 as "divergence" and rounds 4 to 6 as "deepening and integration"
- When working alone, a 5-minute break between rounds makes it easier to shift perspective
- Grouping the ideas at the end, KJ-method style, makes them easier to organize
- Trust that "quantity produces quality" and fill in at least 3 ideas per round

### Next steps
- Prioritize the ideas → **Payoff Matrix** (this skill, 09)
- Organize the pros and cons of an idea → **Pros and Cons Table** (this skill, 08)
- Turn ideas into an execution plan → `/execution` (goal setting and execution management)
- Validate market potential → `/market` (macro environment and industry analysis)

## 02. Mandalart

**Purpose**: Expand ideas in 8 directions from a central theme, spreading your thinking across 81 cells

**When to use**:
- When you want to break a goal down to the level of concrete actions
- When you want to think about a theme exhaustively
- When you want to eliminate gaps in your thinking

**Template**:
```
┌───┬───┬───┐
│   │   │   │
├───┼───┼───┤
│   │Core│   │
├───┼───┼───┤
│   │   │   │
└───┴───┴───┘
```
1. Place the theme in the center
2. Write related elements in the 8 surrounding cells
3. Make each element a new center and expand another 8 cells (81 cells total)

### Worked example (theme: "Reach 100 million yen in annual sales with a new business")

**Central 3x3 grid**:
```
┌──────────────────┬──────────────────┬──────────────────┐
│ Win customers    │ Product strength │ Build the team   │
├──────────────────┼──────────────────┼──────────────────┤
│ Secure funding   │ 100M yen sales   │ Sales strategy   │
├──────────────────┼──────────────────┼──────────────────┤
│ Work efficiency  │ Brand            │ Partners         │
└──────────────────┴──────────────────┴──────────────────┘
```

**Expansion example (3x3 centered on "Win customers")**:
```
┌──────────────────┬──────────────────┬──────────────────┐
│ Trade shows      │ Referral program │ Social media     │
├──────────────────┼──────────────────┼──────────────────┤
│ Seminars         │ Win customers    │ Direct mail      │
├──────────────────┼──────────────────┼──────────────────┤
│ Web ads          │ Industry groups  │ Grow existing    │
└──────────────────┴──────────────────┴──────────────────┘
```

**Expansion example (3x3 centered on "Product strength")**:
```
┌──────────────────┬──────────────────┬──────────────────┐
│ Customer research│ Rival analysis   │ Add features     │
├──────────────────┼──────────────────┼──────────────────┤
│ Improve UI       │ Product strength │ Review pricing   │
├──────────────────┼──────────────────┼──────────────────┤
│ Better support   │ Case studies     │ API integration  │
└──────────────────┴──────────────────┴──────────────────┘
```

### Common mistakes
1. **The central theme is too vague**: Use a measurable goal like "reach 100 million yen in annual sales with a new business" instead of "make the business better"
2. **The 8 elements are at different levels of granularity**: If "marketing" and "make business cards" sit at the same level, expansion becomes hard. Keep them at the same level of abstraction
3. **Writing items unrelated to the central element during expansion**: Each 3x3 grid should contain only content directly tied to its central element. Move loosely related items to another element's expansion

### Tips
- How Shohei Ohtani used it: goal (first-round draft pick by 8 teams) → 8 elements → concrete actions for each element, creating a roadmap to the goal
- If you cannot fill all 8 cells, that is evidence your understanding of the theme is shallow. Treat it as a sign that research is needed
- After completion, pick the 3 items out of 81 with "the biggest impact that can be started right away" as your first actions
- Review it regularly (for example monthly) to check and update progress

### Next steps
- Decide priorities among the 81 cells → **Payoff Matrix** (this skill, 09)
- Turn it into concrete goal setting → `/execution` (OKR, SMART goals, etc.)
- Dig deeper into the issues in each element → `/problem` (problem discovery and definition)
- Design the overall strategy → `/strategy` (strategy and business model design)

## 03. Morphological Analysis

**Purpose**: Break down the elements and systematically generate new ideas from their combinations

**When to use**:
- When you want to explore new product or service concepts exhaustively
- When you want to discover combinations that "seem obvious but do not exist yet"
- When you want to generate ideas logically rather than relying on intuition

**Template**:
| Parameter | Option A | Option B | Option C | Option D |
|----------|--------|--------|--------|--------|
| Axis 1 (e.g. target) | | | | |
| Axis 2 (e.g. place) | | | | |
| Axis 3 (e.g. method) | | | | |
| Axis 4 (e.g. time) | | | | |

**Ideas**: Pick one option from each axis and combine them → total combinations = product of the number of options on each axis

### Worked example (theme: "Developing a new food service")

| Parameter | Option A | Option B | Option C | Option D |
|----------|--------|--------|--------|--------|
| Target customer | Office workers living alone | Families with children | Seniors | Foreign tourists |
| Delivery method | Delivery | Subscription box | Vending machine | Pop-up store |
| Cuisine type | Health food | Regional cuisine | Sweets | Fermented foods |
| Price range | One coin (500 yen or less) | Around 1,000 yen | Premium (3,000 yen and up) | Pay per use |

**Total combinations**: 4 x 4 x 4 x 4 = 256

**Promising combinations**:
- "Seniors × Subscription box × Health food × Around 1,000 yen" → Health food delivered to seniors 3 times a week
- "Foreign tourists × Vending machine × Regional cuisine × One coin" → Regional cuisine vending machines at tourist spots
- "Office workers living alone × Subscription box × Fermented foods × Pay per use" → Gut-health subscription (pay only for what you eat)

### Common mistakes
1. **The choice of axes is biased**: If every axis is about "things", innovation in services and business models is unlikely. Include diverse viewpoints such as "to whom", "where", "when", "how" and "at what price"
2. **Trying to examine every combination**: There is no need to look at all 256. Exclude clearly unsuitable combinations and focus on "surprising combinations"
3. **Options are too conventional**: Put at least one option you think is "impossible" on each axis. Hints for disruptive innovation come from there

### Tips
- 3 to 5 axes are manageable. With 6 or more, the number of combinations becomes too large
- First pick 5 combinations at random and check whether any of them feel "interesting"
- Practice summarizing each combination as a one-line concept statement. This polishes it into a business idea
- Asking "why does this combination not exist yet?" reveals entry barriers and challenges

### Next steps
- Validate the market potential of promising combinations → `/market` (macro environment and industry analysis)
- Check the fit with customer needs → `/customer` (customer understanding and market segmentation)
- Develop the ideas further → **SCAMPER** (this skill, 05)
- Evaluate feasibility as a business → `/strategy` (Business Model Canvas, etc.)

## 04. Osborn's Checklist

**Purpose**: Transform and develop existing ideas or products from 9 viewpoints

**When to use**:
- When you want improvement ideas for an existing product or service
- When you want "something a bit different" but cannot see the direction
- When you want to break through a creative block

**Template**:
| Viewpoint | Question | Ideas |
|------|-----|--------|
| Other uses | Are there other ways to use it? | |
| Adapt | Can you borrow ideas from elsewhere? | |
| Modify | What if you changed the color, shape or meaning? | |
| Magnify | What if you made it bigger, more or stronger? | |
| Minify | What if you made it smaller, fewer or lighter? | |
| Substitute | Can something else take its place? | |
| Rearrange | What if you changed the order or layout? | |
| Reverse | What if you reversed it? Swapped top and bottom, front and back? | |
| Combine | What if you combined or mixed things? | |

### Worked example (subject: "Paper business cards")

| Viewpoint | Question | Ideas |
|------|-----|--------|
| Other uses | Can the card be used for something else? | Card doubles as a coupon, QR code links to a self-introduction video |
| Adapt | Can you borrow from other industries? | Collectible designs like trading cards, AR display of a 3D model |
| Modify | What if you changed the shape or material? | Wooden cards, round cards, scented cards |
| Magnify | What if you made it bigger? | A4-size card with a portfolio, card that doubles as a brochure |
| Minify | What if you made it smaller? | Pin-badge card with an embedded NFC chip, smartphone widget card |
| Substitute | Can something else replace it? | Exchange LINE contacts instead of cards, digital card on a blockchain |
| Rearrange | What if you changed the order? | Exchange cards at the end of the meeting (handing it over after the conversation makes it memorable) |
| Reverse | What if you reversed it? | "Reverse card" where the other person writes your details, a policy of not accepting cards |
| Combine | What if you combined it? | Card + smartphone stand, card + plant seeds (growing it keeps you in mind) |

### Common mistakes
1. **Stopping at one idea per viewpoint**: Produce at least 2 to 3 per viewpoint. The first idea is one anyone would think of. Originality appears from the second onward
2. **Judging feasibility right away**: At the checklist stage, judge only by "is it interesting?". Evaluate feasibility in a later step
3. **Starting with a vague subject**: Narrow it to one concrete object like "paper business cards" rather than "improve the service"

### Tips
- Going through all 9 viewpoints is important. Unexpected ideas often come from the viewpoint you skipped as "irrelevant"
- In team work, assigning one viewpoint per person is efficient
- Sorting the ideas by "can do now / takes time" and "low cost / high cost" reveals the next action
- Applying this checklist to a competitor's product gives hints for differentiation

### Next steps
- Proceed with transformations more systematically → **SCAMPER** (this skill, 05)
- Prioritize the ideas → **Payoff Matrix** (this skill, 09)
- Visualize as a user experience → **Storyboard** (this skill, 07)
- Build improvements into business processes → `/improvement` (process improvement and optimization)

## 05. SCAMPER

**Purpose**: 7 transformation techniques developed from Osborn's Checklist. Transform ideas with a more structured approach

**When to use**:
- When you want to innovate on an existing product or service
- When you want to use Osborn's Checklist more deeply
- In product development or service improvement workshops

**Template**:
| Technique | Question | Example prompts | Ideas |
|------|-----|-------------|--------|
| **S**ubstitute | What can be replaced? | Materials? Processes? People? Places? | |
| **C**ombine | What can be combined? | Functions? Purposes? Materials? | |
| **A**dapt | What can be imitated or adapted? | Other industries? Nature? History? | |
| **M**odify | What can be changed or emphasized? | Size? Color? Shape? Speed? | |
| **P**ut to other uses | Can it serve another purpose? | Other customers? Other markets? By-products? | |
| **E**liminate | What can be removed? | Unneeded features? Steps? Rules? | |
| **R**earrange/Reverse | What if reversed or reordered? | Order? Cause and effect? Roles? | |

### Worked example (subject: "A conventional fitness gym")

| Technique | Question | Ideas |
|------|-----|--------|
| Substitute | What if AI replaced the trainers? | AI posture-analysis camera + automatic form correction. One third the labor cost, 24-hour service |
| Combine | Gym × coworking space? | A "moving office" with built-in cycles of 30 minutes of desk work → 15 minutes of exercise |
| Adapt | What if we adapted mechanics from the game industry? | RPG-style fitness: exercise earns experience points and your character grows. Cooperative quests in guilds (teams) |
| Modify | What if a session were extremely short? | A gym specializing in 7-minute HIIT. No changing, shoes on. Located inside train stations |
| Put to other uses | Can the gym equipment serve another purpose? | Open at night to seniors as a rehabilitation facility. Athletes by day, care prevention by night |
| Eliminate | What if we dropped the membership system? | Fully pay-as-you-go. Billed by the minute. Pay only for what you use |
| Rearrange | What if we reversed "going to the gym"? | The gym comes to you: a mobile gym van loaded with training equipment arrives at your door |

### Common mistakes
1. **Using SCAMPER only in order**: The order is free. You can start from the most stimulating viewpoint. In fact, starting from "E (Eliminate)" makes the essence easier to see
2. **Settling for one idea per technique**: Produce at least 2, ideally 3 or more ideas per technique. The first one is often "ordinary"
3. **The subject is too big**: Focus on concrete elements such as "the reception process" or "the monthly billing model" rather than "the whole company"

### Tips
- **E (Eliminate) is the most powerful**: "What happens if we remove this?" is often the starting point of disruptive innovation (example: Uber = taxis minus vehicle ownership)
- Crossing the ideas from the 7 techniques raises originality further
- Applying SCAMPER to a competitor's service gives hints for a differentiation strategy
- Making a habit of applying SCAMPER to your own service regularly (for example quarterly) leads to continuous innovation

### Next steps
- Turn ideas into a user experience → **Design Thinking** (this skill, 06)
- Evaluate feasibility → **Payoff Matrix** (this skill, 09)
- Check the fit with customer needs → `/customer` (customer understanding and market segmentation)
- Design the business model → `/strategy` (Business Model Canvas, etc.)

## 06. Design Thinking (5 steps)

**Purpose**: Discover problems with a human-centered approach and validate quickly with prototypes

**When to use**:
- When you do not know the user's real problem
- When you want to think needs-driven rather than technology-driven
- When you want to validate an idea early
- In the early concept stage of a new service or product

**Template**:
| Step | Content | Output |
|---------|------|-----------|
| 1. **Empathize** | Observe and interview users | Insights and discoveries |
| 2. **Define** | Identify the real problem | POV (point of view) statement |
| 3. **Ideate** | Generate many ideas | Idea list |
| 4. **Prototype** | Give it form quickly | Prototype |
| 5. **Test** | Have users try it | Feedback and improvements |

**POV statement**: "(User) needs (need) because (insight)"

### Worked example (theme: "Hospital waiting time problem")

| Step | Content | Output |
|---------|------|-----------|
| Empathize | Interviewed 20 patients. Observed behavior in the waiting room. Heard from reception staff | Patients are stressed less by "the length of the wait" than by "not knowing how much longer they will wait". Seniors also struggle to find a seat |
| Define | The root of the anxiety is "lack of information" and "a sense of wasted time" | "Outpatients need options that let them use waiting time meaningfully, because uncertain waiting times create helplessness and stress" |
| Ideate | 30 ideas through Brainwriting → narrowed to 5 by voting | (1) Real-time queue position display (2) Call-back app that lets patients leave the building (3) Health consultations during the wait (4) Partnership with nearby cafes (5) Online pre-consultation questionnaire |
| Prototype | Built the call-back app UI as a paper mockup. Reproduced the queue display on a simple web page | Paper prototype of 3 smartphone screens. Minimal function: enter your reception number and see "about X minutes left" |
| Test | Showed the prototype to 10 patients for feedback | "Just seeing the time is reassuring", "Seniors struggle with smartphones → in-hospital monitor display also needed", "If I can leave, I would like to pick up medicine at the nearby pharmacy first" |

### Common mistakes
1. **Skipping the Empathize step**: Assuming "I already understand how users feel" and jumping to solutions. Interview at least 5 people
2. **The problem definition is actually a solution**: "We need an app" is a solution, not a problem definition. "Stress caused by uncertain waiting times" is a problem definition
3. **Spending too long on the prototype**: Do not aim for perfection. Something made with pen and paper in 30 minutes is enough. The goal is "to learn", not "to build a finished product"

### Tips
- The 5 steps are iterative, not linear. Going back to Empathize based on what you learn in Test is important
- Reframing the problem as "How Might We..." broadens ideation
- In the Ideate step, combine other frameworks from this skill (Brainwriting, SCAMPER, etc.)
- Build prototypes "in order to fail". You learn the most from failure
- Speed matters. Run one cycle in 1 to 2 weeks

### Next steps
- Use in the Ideate step → **Brainwriting** (this skill, 01), **SCAMPER** (this skill, 05)
- Visualize the user experience → **Storyboard** (this skill, 07)
- Understand users deeply → `/customer` (Persona, Customer Journey Map, etc.)
- Build strategy from test results → `/strategy` (strategy and business model design)
- Analyze root causes of the problem → `/problem` (problem discovery and definition)

## 07. Storyboard

**Purpose**: Draw an idea or user experience as a visual story in time order

**When to use**:
- When you want to communicate an idea to others
- When you want to design or check the flow of a user experience
- When you want to list a service's touchpoints
- When you want to win empathy in a presentation

**Template**:
| Scene | 1. Trigger | 2. Action | 3. Experience | 4. Result |
|-------|-----------|--------|--------|--------|
| Situation | | | | |
| User's action | | | | |
| Emotion | | | | |
| Touchpoint | | | | |

**How to use**: You do not need to be able to draw. Even in text form, what matters is visualizing the flow of scenes.

### Worked example (theme: "Customer support by AI chatbot")

| Scene | 1. Trigger | 2. First contact | 3. Problem solving | 4. Follow-up |
|-------|-----------|------------|-----------|---------------|
| Situation | 2 a.m., a newly bought appliance does not work. Needs it before guests arrive tomorrow | Clicks the chat icon on the website and the AI answers "Good evening" | AI asks about the symptoms and walks through the reset steps. Shows the steps with images | Next morning, a follow-up email arrives: "Was last night's issue resolved?" |
| User's action | Searches "product name broken" on a smartphone → official site | Types "it won't turn on". Answers the AI's questions | Follows the steps. Asks extra questions about unclear points along the way | Replies "Solved!" and asks another question while at it |
| Emotion | 😰 Panic and anxiety: "It's the middle of the night, I can't call support" | 😮 Surprise: "They respond even at this hour" | 😊 Relief: "Easy to follow. I can fix this myself" | 😍 Delight: "They follow up this far?" |
| Touchpoint | Google search → official site | Chat widget → AI response | Chat screen → image display → video link | Follow-up email → chat history |

### Common mistakes
1. **Drawing only the happy path**: Also draw scenes for "when things go wrong". Error cases and moments where users get lost are where service design shows its skill
2. **Leaving out emotional changes**: The core of a storyboard is the change in the user's emotions. Without emotions in each scene it becomes a mere procedure manual
3. **Too many or too few scenes**: 4 to 8 scenes is appropriate. Too many blurs the focus, too few hides the flow of the experience

### Tips
- Making two versions, "before" and "after", communicates the value of a proposal clearly
- Noting "risk of drop-off here" at each scene reveals UX improvement points
- Setting up a persona (a concrete person) before drawing the story adds realism
- After building it in text, developing it into sketches or screen mockups helps align the team's understanding
- Making multiple storyboards for one idea with different personas tests how broadly the service applies

### Next steps
- Design personas → `/customer` (customer understanding and market segmentation)
- Analyze the issues in each scene → `/problem` (problem discovery and definition)
- Structure it for a presentation → `/communication` (communication and presentation)
- Improve the service process → `/improvement` (process improvement and optimization)

## 08. Pros and Cons Table

**Purpose**: Line up pros and cons side by side to support decision making

**When to use**:
- When you are torn over an important decision
- When you want to organize an emotionally charged topic objectively
- When stakeholders disagree
- When you want to compare several options

**Template**:
**Theme**: _______________

| Pro (benefits) | Importance | Con (drawbacks) | Importance |
|-------------------|-------|-------------------|-------|
| | High/Med/Low | | High/Med/Low |
| | High/Med/Low | | High/Med/Low |
| | High/Med/Low | | High/Med/Low |

**Verdict**: 

### Worked example (theme: "Introducing a fully remote work policy")

| Pro (benefits) | Importance | Con (drawbacks) | Importance |
|-------------------|-------|-------------------|-------|
| Zero commute → employees gain an average of 2 hours/day of free time | High | Fewer opportunities for face-to-face communication | High |
| Lower office rent (about 30 million yen per year) | High | Onboarding new hires becomes difficult | High |
| Can hire top talent from across the country and abroad | High | Hard to maintain team cohesion and company culture | Med |
| Easier to balance with childcare and caregiving, lowering turnover | Med | Higher information security risk | Med |
| Better business continuity during natural disasters | Med | Supporting employees without a proper home work setup | Low |
| Employees' autonomy and self-management improve | Low | More complex labor management (tracking overtime, etc.) | Med |

**Verdict**: On the Pro side, "cost reduction", "talent acquisition" and "lower turnover" are high importance with a large management impact. On the Con side, "communication" and "onboarding" are high importance but can be mitigated with a hybrid model (2 office days a week). → **Recommend phased introduction as a hybrid remote policy**

### Common mistakes
1. **Far more Pros (or far more Cons)**: Building the table after the conclusion is already decided skews it. Make a deliberate effort to list 5 or more on the opposing side. Assign a "devil's advocate"
2. **Rating everything "High"**: Without differences in importance, the table gives no basis for a decision. Ask "would the decision change without this item?" to set priorities
3. **Judging on qualitative items only**: Quantify wherever possible. Quantifying "cost reduction" as "30 million yen saved per year" improves decision accuracy

### Tips
- Rating "certainty" in addition to importance improves accuracy (a Con that will surely happen vs. a Pro that may not)
- With several options, make a table for each option and compare them side by side
- Asking "is there a way to resolve this Con?" produces ideas for conditional approval or phased introduction
- Keep the table after the decision and look back at what actually happened. This improves decision quality
- Have each stakeholder write their own table and compare them to reveal gaps in understanding

### Next steps
- More quantitative evaluation → **Payoff Matrix** (this skill, 09)
- Execution plan for the decision → `/execution` (goal setting and execution management)
- Analyze the impact on the organization → `/organization` (organization and team management)
- Communicate the decision to stakeholders → `/communication` (communication and presentation)
- Analyze the root causes of the Cons → `/problem` (problem discovery and definition)

## 09. Payoff Matrix

**Purpose**: Evaluate ideas on two axes, "impact" and "feasibility (cost and effort)", and prioritize them

**When to use**:
- When there are too many ideas and you do not know where to start
- When resources (time, budget, people) are limited
- When you want team agreement on priorities
- In quarterly planning or sprint planning

**Template**:
|  | Easy to implement | Hard to implement |
|---|--------|--------|
| **Impact: high** | Quick Win (do now) | Major project (plan it) |
| **Impact: low** | Fill-in (if time allows) | Money Pit (skip) |

**Idea placement**:
- Quick Win:
- Major project:
- Fill-in:
- Skip:

### Worked example (theme: "Prioritizing sales improvement measures for an e-commerce site")

|  | Easy to implement (within 1 month, 1 million yen or less) | Hard to implement (3 months or more, 5 million yen or more) |
|---|--------|--------|
| **Impact: high** (expected sales increase of 10% or more) | **Quick Win** | **Major project** |
| **Impact: low** (expected improvement under 5%) | **Fill-in** | **Skip** |

**Idea placement**:
- **Quick Win (do now)**:
  - Automated cart-abandonment emails (impact: 15% better conversion rate, effort: 2 weeks)
  - Optimize CTA button color and position on product pages (impact: 20% higher click rate, effort: 3 days)
  - Introduce review request emails (impact: 3x more reviews → higher trust, effort: 1 week)
- **Major project (plan it)**:
  - Introduce an AI recommendation engine (impact: 30% higher average order value, effort: 6 months, cost: 8 million yen)
  - Develop a mobile app (impact: 2x repeat rate, effort: 8 months, cost: 15 million yen)
- **Fill-in (if time allows)**:
  - Expand the FAQ page (impact: 20% fewer inquiries, effort: 2 weeks)
  - Add social sharing buttons (impact: 5% more traffic, effort: 1 day)
- **Skip (Money Pit)**:
  - 3D views for all products (impact: unknown, effort: 12 months, cost: 20 million yen)
  - Virtual store in the metaverse (impact: buzz only, effort: 10 months, cost: 30 million yen)

### Common mistakes
1. **Vague criteria for "impact" and "feasibility"**: Define concrete thresholds for "high", "low", "easy" and "hard" in advance. Draw the lines with amounts, periods and percentages as in the example above
2. **Putting everything in Quick Win**: Beware of optimism bias. Estimate feasibility for "the worst case". Estimate impact "conservatively"
3. **Stopping after placement**: The matrix is a decision tool. It is not complete until you decide actions such as "start with Quick Wins in order" or "put major projects in next period's plan"

### Tips
- Set concrete numeric criteria for each axis (e.g. impact = sales impact, feasibility = effort × cost)
- In a team, have each person place the ideas individually first, then compare. Differences in perception become visible
- Also set timelines, such as "start Quick Wins this week" and "add major projects to next month's roadmap"
- Re-evaluate quarterly. Technical progress and market changes can turn "hard" into "easy"
- "Skip" does not mean "rejected forever". It means "not now", and should be reconsidered when conditions change

### Next steps
- Plan the execution of Quick Wins → `/execution` (goal setting and execution management)
- Build the strategy for major projects → `/strategy` (strategy and business model design)
- Identify issues before execution → `/problem` (problem discovery and definition)
- Set up the team structure → `/organization` (organization and team management)
- Raise feasibility by streamlining processes → `/improvement` (process improvement and optimization)

## How to run the conversation

### Step 1: Interview
To understand the user's theme and situation accurately, confirm the following:

1. **Confirm the theme**: "What do you want to think about?"
2. **Confirm the goal**: "Do you want to generate new ideas, or evaluate and select ideas you already have?"

### Step 2: Framework selection
Based on the interview, propose the best framework:

| User's situation | Recommended framework | Reason |
|-------------|----------------|------|
| "I have zero ideas" | Brainwriting or Mandalart | Best for diverging from zero |
| "I want to improve an existing product" | Osborn's Checklist or SCAMPER | Specialized in transforming and developing existing things |
| "I want to combine elements of a new service" | Morphological Analysis | Systematic exploration of combinations |
| "I want to solve a user's problem" | Design Thinking | Human-centered approach |
| "I want to communicate an idea to others" | Storyboard | Visualizing and sharing the experience |
| "I can't decide which option to pick" | Pros and Cons Table | Organizing and visualizing pros and cons |
| "I want to prioritize many ideas" | Payoff Matrix | Evaluation by impact × feasibility |

**Recommended framework combinations**:
- **Diverge → converge**: Brainwriting → Payoff Matrix
- **Improve → evaluate**: SCAMPER → Pros and Cons Table
- **Explore → visualize → validate**: Morphological Analysis → Storyboard → Design Thinking
- **Set goals → break down into actions**: Mandalart → OKR in `/execution`

### Step 3: Fill in the template interactively
- Do not try to fill everything at once. Proceed one section at a time through dialogue
- When the user's answer is abstract, dig deeper with "Specifically?" or "For example?"
- When stuck, offer a different perspective ("What if you looked at it from the opposite side?" "Where will this be in 5 years?")
- Insert interim summaries as appropriate: "Let me summarize what we have so far"

### Step 4: Complete and output
- Output the completed worksheet formatted in Markdown
- Summarize the main findings and insights in 3 points or fewer
- Propose the next actions (what, by when, who)
- Suggest related frameworks (next steps)

### Step 5: Follow-up
- "Based on this result, is there any part you want to explore further?"
- "Do you want to continue by combining it with another framework?"
- As needed, suggest connecting to other skills (`/strategy`, `/problem`, `/customer`, etc.)
